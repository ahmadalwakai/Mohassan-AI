خادم MCP جيد يعطي المساعد أدوات قليلة واضحة تنجز مهام حقيقية.

## متى تُستخدم
- عند ربط خدمة أو API بمساعد ذكي عبر بروتوكول MCP.

## ما أحتاجه منك
- الخدمة وتوثيق الـ API، والمهام التي سيؤديها المساعد بها.
- أين يعمل الخادم: محليًا (stdio) أم عن بعد (HTTP).

## الخطوات
1. اكتب المهام الحقيقية أولًا، ثم اختر أدوات تخدمها؛ أداة لكل سير عمل خير من أداة لكل نقطة API.
2. سمِّ الأدوات بأسماء واضحة متسقة، مثل `search_issues` و`create_issue`.
3. حدد لكل أداة مخطط مدخلات صارمًا ووصفًا يقول متى تُستخدم.
4. أعد نتائج مختصرة مع ترقيم صفحات؛ سياق النموذج محدود.
5. اجعل رسائل الخطأ عملية: ما الخطأ، وكيف يُصلح.
6. ابدأ بـ TypeScript وحزمة MCP الرسمية، وبنقل HTTP عديم الحالة للخوادم البعيدة.
7. اختبر كل أداة، ثم اكتب عشرة أسئلة تقييم واقعية وتحقق أن المساعد يحلها بالأدوات.

## شكل الجواب
- جدول الأدوات: الاسم، والغرض، والمدخلات، والمخرجات؛ ثم النقل، والمصادقة، وخطة الاختبار.

## تحقق قبل التسليم
- هل تعمل كل أداة بمفردها وتعيد خطأً مفهومًا؟

## أخطاء شائعة
- تحويل كل نقطة API إلى أداة بلا تمييز.
- نتائج ضخمة تملأ السياق.
