# المراجعة المعمارية المستقلة

التاريخ: 2026-11-04. النطاق: مراجعة ملف التعليمات، فحص أن المستودع فارغ من الكود، ومراجعة `ARCHITECTURE.md` قبل التنفيذ. لم تكتب هذه المراجعة كودًا ولم تعدل الملف الأصلي للتعليمات.

## القرار

**صالح للبدء في شريحة Foundation + Runtime بمهمة تشخيص آمنة واحدة** بعد إدراج التصحيحات في المواصفات. بدء التنفيذ مصرح به من طلب المستخدم. لا توجد تعديلات لكود قائم، والمراجعة المستقلة المطلوبة قبل البناء أُنجزت. هذا القرار ليس موافقة نشر ولا شهادة أمان إنتاجي.

المعمارية تحفظ قدرات الخطة الواسعة، وتؤجل تنفيذ الوحدات بحسب الاعتماديات. اختيار عملية واحدة لـ Better Auth وKysely وPGlite في التطوير صالح بشرط عدم فتح المخزن نفسه من Next أو عامل آخر. التوافق مع Neon والتزامن متعدد العمال يحتاجان اختبارات PostgreSQL منفصلة؛ لا تستنتجهما اختبارات PGlite.

## تصحيحات أدرجت في المسودة

1. حماية إنشاء أول مالك برمز إعداد محلي لا يرجعه HTTP، وقفل متسلسل وقيد singleton. localhost وحده لا يحمي المسار خلف وكيل Next. HTTP bootstrap معطل إنتاجيًا.
2. فصل وجود إعداد Groq عن تحقق الاتصال، وعدم تنفيذ طلب مدفوع عند عرض لوحة التحكم. تفعيل plan.draft اختياري بعد اختبار حدوده.
3. موافقة مرتبطة ببصمة المدخلات والإصدار والمالك والانتهاء، مع إعادة فحصها واستهلاكها ذريًا قبل التنفيذ. المحاولات الجديدة لا ترث موافقة مستهلكة تلقائيًا.
4. shadow يمنع استدعاء أي أداة ذات أثر، ولا يتحول إلى صلاحية تنفيذ لاحقًا.
5. تخصيص تسلسل أحداث ضمن المعاملة وفرض fencing على تحديثات العامل؛ خطوة واحدة للشريحة الأولى، وtask_steps قبل توسيع المهام متعددة الأدوات.
6. منع كشف أسرار أو مسارات شخصية في التشخيص وlogs، وفحص مستقل للنتائج الفعلية.
7. تثبيت trusted origin وإعداد proxy، وعدم الثقة بترويسات يحددها العميل، وحظر إعدادات التطوير في الإنتاج.
8. توضيح حالات offline والتوقيت وإعادة المحاولة بمفتاح ثابت، وعدم حفظ بيانات المالك أو الرموز في localStorage.

## معايير قبول الشريحة

لا تعد الشريحة مكتملة بمجرد نجاح build. يلزم إثبات التدفق: إعداد مالك → دخول → إنشاء مهمة → موافقة عند الحاجة → تشغيل → تحقق مستقل → أحداث ونتيجة → بقاء البيانات بعد إعادة التشغيل.

| المجال | معيار القبول |
|---|---|
| الإعداد | الرمز الخاطئ وOrigin المخالف مرفوضان؛ طلبان متزامنان لا ينشئان أكثر من مالك؛ التسجيل العام مرفوض |
| المصادقة | غياب الجلسة يرفض API؛ خروج المستخدم يبطل الجلسة؛ لا أسرار في responses أو logs |
| الملكية | كل قراءة أو تعديل لمهمة غير مملوكة يرفض دون كشف بياناتها |
| العقود | المدخلات غير الصحيحة والقدرات غير النشطة مرفوضة قبل enqueue؛ أخطاء مفهومة بالعربية في الواجهة |
| Idempotency | مفتاح ومدخلات متماثلان يعيدان task نفسها؛ مدخلات مختلفة بالمفتاح نفسه تعيد 409؛ retry للواجهة يحافظ على المفتاح |
| الموافقة | assisted لا ينفذ قبل الموافقة؛ موافقة منتهية أو لمدخلات/إصدار مختلف تمنع التنفيذ؛ سباق approve/cancel لا يولد انتقالًا غير صالح |
| التنفيذ | نتيجة تشخيص حقيقية وبنية typed وحدود زمن؛ لا أوامر shell أو اتصال حسابات أو نشر |
| التحقق | إخفاق verifier يمنع completed؛ لا يُقبل ادعاء النجاح الصادر من executor وحده |
| الإلغاء | الإلغاء يمنع claims والخطوات الجديدة؛ لا إعلان نجاح بعد اعتماد إلغاء؛ حالة الأثر غير المحسوم تتطلب reconciliation |
| الديمومة | restart يحتفظ بالمهمة والأحداث؛ lease منتهية تستعاد فقط لأداة replaySafe؛ عامل قديم لا يعتمد النتيجة بعد فقد token |
| الأحداث | تسلسل فريد مرتب، معاملة تجمع الحدث وتغيير الحالة، ولا سر في البيانات المرئية |
| الواجهة | RTL متجاوب، loading/empty/error/offline/retry/permission states، إدخال بلوحة المفاتيح، وعدم وجود بيانات نجاح مصطنعة |
| التشغيل | typecheck واختبارات الوحدة/SQL/API وبناء Next واختبار متصفح للتدفق الأساسي |

اختبارات SQL المحلية تثبت المنطق والديمومة المحلية. يلزم قبل تشغيل إنتاجي أو ادعاء دعم عدة عمال: PostgreSQL/Neon فعلي، اختبار claim متزامن وlease fencing والمعاملات والتسجيل والمخطط النهائي لـ Better Auth.

## حدود غير محسومة قبل الإنتاج

لا بيانات اعتماد أو خدمة استضافة دائمة أو سياسة احتفاظ/RPO/RTO معتمدة. لا تكامل Google Ads أو Windows أو iPhone جاهزًا في هذه الشريحة. لا يُعلن اكتمال المنصة أو تحسن تعلم آلي أو تحمل أعطال إنتاجي من هذه المراجعة. حالة كل مرحلة توثق بالاختبارات والميزات المنفذة فعلًا.

## المراجع الداخلة في المراجعة

- `instractions and plan.txt`: المتطلبات الأصلية.
- `docs/ARCHITECTURE.md`: حدود الخدمات والعقود والمراحل بعد التصحيح.

هذه مراجعة تصميم مستقلة؛ توافق APIs الفعلي يُحسم بالإصدارات المثبتة واختبارات التنفيذ، وليس بافتراض أن المخطط وحده يثبت التوافق.
