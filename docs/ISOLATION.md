# عزل اختبارات البرمجة في Windows

التاريخ: 2026-11-04. الموفر الحالي `windows-appcontainer`، وقيمة `isolation` هي `appcontainer`. يشغّل Node داخل حدود AppContainer وJob Object يفرضها Windows، ويشارك نواة النظام مع المضيف. لا توجد آلة افتراضية أو حاوية Linux ضمن هذا الموفر.

## ما يعمل على المضيف وما يدخل الحد المعزول

خدمة التحكم وGit وموائم Groq ومشغّل PowerShell/C# مكونات موثوقة من المشروع. مشغّل C# ينشئ العملية المعزولة، ولا يفسر كود المشروع داخل PowerShell أو عملية الخدمة. فحص صياغة JavaScript/TypeScript واختبارات المشروع يشغلان Node المنسوخ داخل AppContainer فقط؛ لا fallback إلى تنفيذ المشروع على المضيف عند تعذر العزل.

ترسل طبقة البرمجة نسخة نصية محددة من الملفات والاختبارات المحمية. لا يمنح الموفر AppContainer إذنًا على المشروع الأصلي أو Git worktree أو جذر مساحة التحكم. يمنح نسخة المصدر ونسخة Node صلاحية القراءة والتنفيذ، ومجلد TEMP منفصلًا صلاحية الكتابة. لا يمنح أصل نسخة المصدر `DELETE_CHILD`، وتؤكد التجربة رفض تعديل ملف الاختبار وحذفه. يتجنب Node فحص realpath لأسلاف القرص باستخدام `--preserve-symlinks`؛ لا تضاف صلاحية إلى `C:\` لحل ذلك.

لا تنسخ `.git` أو `.env` أو مجلدات الاعتمادات أو المسارات المحمية إلى نسخة الاختبار. المسارات النسبية مقيدة، وتمنع traversal وUNC/ADS وأسماء أجهزة Windows والنهايات الملتبسة. تحسب الخدمة SHA-256 من JSON للملفات `{path,content}` مرتبة بالمقارنة `en`، وتعيد حساب بصمة النسخة بعد الاختبار قبل قبول الإيصال.

## تسلسل إنشاء العملية الموثوق

1. إنشاء AppContainer profile مؤقت فريد بلا capability SIDs، ومنح صلاحيات المجلدات المؤقتة المحددة فقط.
2. إنشاء Job بحدود ثابتة و`KILL_ON_JOB_CLOSE` مع تعطيل breakaway.
3. إنشاء Node في حالة suspended باستخدام `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`، وبيئة صريحة خالية من بيئة الخدمة.
4. حصر المقابض الموروثة في stdin من NUL وstdout/stderr عبر pipes؛ لا تورث مقابض قاعدة البيانات أو ملفات الاعتماد أو Job.
5. إسناد العملية إلى Job قبل استئنافها، وقراءة token والحدود من Windows: `TokenIsAppContainer=true`، وSID مطابق للـ profile، وIntegrity RID لا يتجاوز 4096، وعدد capabilities يساوي صفرًا، وحد العمليات والذاكرة وkill-on-close/no-breakaway مطابق.
6. استئناف العملية فقط بعد اجتياز هذه الفحوص. فشل أي خطوة يغلق التنفيذ ويرفض الإيصال.

هذه فحوص أصلها native helper الموثوق؛ كود Node أو نص stdout لا يستطيع إعلان `isolationVerified=true` بنفسه. تستخدم AppContainer صلاحيات SID وDACL ومستوى السلامة المنخفض؛ وتتكفل Job Objects بقيود مجموعة العمليات ودورة إنهائها. [شرح Microsoft لـ AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)، [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

## الحدود الحالية

| المورد | الحد أو السياسة |
|---|---|
| الشبكة | لا network capabilities؛ فحص بدء التشغيل يقارن اتصالًا ناجحًا على المضيف مع اتصال محجوب داخل AppContainer |
| الذاكرة | 512 MiB للعملية ولـ Job؛ تضبط الحدود قبل Resume ويُراجع حد العملية من native Job |
| المعالج | Job CPU hard cap بنسبة 25% |
| العمليات | عملية واحدة؛ لا breakaway أو توريث لمقبض Job |
| وقت الاختبار | مهلة أوامر مطلوبة، مقيدة حتى 20 ثانية، مع حد نهائي مستقل للمشغّل الموثوق لا يتجاوز 90 ثانية |
| stdout/stderr | يحتفظ native helper حتى 64 KiB لكل stream وأمر ويستمر في تصريف الباقي؛ الرد المجمع محدود أيضًا |
| المدخلات | موفر العزل حتى 100 ملف و512 KiB نص؛ شريحة البرمجة تفرض حدودًا أصغر قبل استدعائه |
| الملفات | نسخة المصدر وNode للقراءة والتنفيذ، وTEMP منفصل قابل للكتابة؛ يطابق hash الإيصال النسخة المرسلة |
| البيئة | قائمة صريحة لمسارات Windows/Node وTEMP؛ لا تورث GROQ_API_KEY أو DATABASE_URL أو NODE_OPTIONS من الخدمة |

فحص الصياغة يستخدم `node --check` داخل AppContainer. الاختبارات تستخدم Node المدمج مع `--test --test-isolation=none` حتى لا يحتاج مشغّل الاختبارات إلى عملية فرعية. الأوامر ثابتة، والملفات تمرر كمعاملات مقيدة؛ لا npm أو تثبيت اعتمادات أو shell أو أوامر حرة من النموذج. يتوقف التسلسل عند أول فشل صياغة، فلا يمكن لاختبار غير مرتبط ينجح لاحقًا إخفاءه.

## الإلغاء والتنظيف

يسجل المضيف إلغاءً في marker خارج صلاحيات نسخة المصدر، ويراقبه native helper بفاصل 50 ms ثم يستدعي `TerminateJobObject`. يوجد إنهاء احتياطي للمشغّل؛ إغلاق مقابضه يفعل `KILL_ON_JOB_CLOSE` للعملية المعزولة أيضًا. اختبر الإلغاء باستخدام عملية Node مستمرة، ثم تحقق المضيف من أن PID لم تعد حية.

تغلق مقابض العملية والخيوط والـ Job والـ pipes، ويُطلب حذف profile المؤقت من Windows. يتحقق تنظيف ملفات النسخة من المسار المطلق الحقيقي وانتمائه إلى مجلد TEMP أنشأه هذا التشغيل قبل أي حذف متكرر. تستخدم كل تجربة نسخة مستقلة؛ لا ينظف الموفر worktree أو ملفات المشروع الأصلي.

## الأدلة المنفذة

- `scripts/probe-sandbox.ts`: تحقق native token/Job قبل التنفيذ، ورفض قراءة sentinel صناعي خارج النسخة وتعديل المصدر وحذفه، ونجاح كتابة TEMP، وعدم توريث متغير صناعي من المضيف.
- فحص الشبكة: المضيف استطاع الوصول إلى listener محلي وإلى `1.1.1.1:443`؛ العملية المعزولة تلقت حجب loopback من Windows وفشل الاتصال الخارجي بـ `EACCES`. المهلة المصطنعة دون دليل OS لا تقبل بوصفها نجاحًا للفحص.
- `packages/sandbox/src/sandbox.test.ts`: 16 اختبارًا ناجحًا في التحقق المسجل، تشمل صلاحية المسارات، والبصمة، والحد الفعلي، والصياغة، والاختبارات، ومنع العملية الفرعية، والمهلة، والإلغاء وانتهاء العملية.
- `tests/sandbox-control-plane.test.ts`: اختبار Windows منفرد ناجح. تحقق المضيف من وجود `.env` بوصفها metadata فقط؛ حاول Node المعزول فتحها للقراءة وأغلق descriptor فورًا لو نجح، دون قراءة أو طباعة أي byte. رفض Windows الفتح، ولم توجد GROQ_API_KEY أو DATABASE_URL في بيئة Node. لم يقرأ الاختبار محتوى ملف إعداد المضيف.

فحص `.env` يغطي ACL الخاصة بالملف في هذه البيئة وقت الاختبار؛ لا يثبت سرية كل ملف آخر أو كل إعداد Windows مستقبلًا. عند تعذر إثبات أي حد أساسي، ترجع available=false وتتوقف شريحة تنفيذ المشروع.

## القيود المتبقية

العزل يعتمد على Windows وDACL، وقد يسمح النظام بقراءة موارد عامة ممنوحة لتطبيقات AppContainer؛ ليس نظام ملفات افتراضيًا محصورًا حصريًا في نسخة المشروع. تحتاج ملفات control plane الحساسة، ومنها `.env` وأسرار `.data` وبيانات الجلسات، إلى ACL خاصة بالمالك وAdministrators وSYSTEM. نمط Unix `0600` وحده ليس ضمان ACL على Windows، ولا تضاف صلاحيات AppContainer لتلك الموارد.

TEMP يستخدم قرص المضيف، ولا توجد حصة قرص صلبة خاصة به حاليًا. المهلة والذاكرة والـ Job حدود فعلية، لكنها لا تعوض حصة قرص أو عزل نواة مستقلة. هذا profile مخصص لاختبارات Node المدمجة لمشاريع صغيرة بلا اعتمادات؛ المتصفحات والحاويات والبناء الذي يحتاج شبكة أو عدة عمليات غير مدعومة به حاليًا.

يتطلب إثبات الشبكة الأول وجود هدف يمكن الوصول إليه من المضيف؛ فشل control probe يعطل الموفر بدل اختلاق نجاح. تخزن نتيجة available في مثيل الموفر، بينما تعاد فحوص token وJob لكل عملية. لا تُعد هذه الأدلة اعتمادًا عامًا للإنتاج أو دليلًا على اكتمال Coding Lab أو الاستوديو البصري.

## تدقيق العزل الفعلي — 2026-11-05

نُفذ التدقيق على Windows 11 بناء 26300 بنسخة مؤقتة من المشغّل خارج المستودع، ودون تعديل كود المشروع. استُخدمت مجلدات canary ولم يُقرأ محتوى أي ملف سري. الفحوص تحقق من الفتح أو السرد فقط.

### سبب توقف الفحص

توقف `WindowsAppContainerSandbox.available()` على هذا الجهاز لسببين متتاليين، وكلاهما فشل آمن:

1. PowerShell 7 مثبت من Microsoft Store، و`where.exe` يعيد اسماً مستعاراً يرفضه `realpath` بخطأ `EACCES`.
2. عند تمرير المسار الحقيقي، يعمل المشغّل داخل حزمة MSIX، فينشئ Windows حاوية فرعية تحت `microsoft.powershell_8wekyb3d8bbwe`. يرث الرمز قدرة واحدة من الحزمة، فيفشل شرط `capabilityCount==0`، ويختلف مسار TEMP عما يتوقعه `Runner.cs`.

الإثبات: تشغيل المشغّل عبر Windows PowerShell غير المحزّم في `System32`، مع شرط `capabilityCount==0` كما هو، نجح فحص الرمز وحدود Job. احتاج ذلك تعديلين في نسخة مؤقتة ليتوافق `Runner.cs` مع C# 5. لم تُحدد هوية القدرة الموروثة، ولم تطابق 695 اسماً مرشحاً.

### الإصلاح المنفذ

يعمل المشغّل الآن من Windows PowerShell في `System32` بمسار ثابت لا يُحل من PATH، ويرفض `Runner.cs` أي مضيف محزّم عبر `GetCurrentPackageFullName`. بقي شرط `capabilityCount==0` كما هو. تثبت اختبارات `packages/sandbox/src/sandbox.test.ts` رفض PowerShell المحزّم ونقل النص العربي سليماً.

### الحكم

العزل الحالي حد نظام حقيقي يحجب الأسرار وملفات المستخدم والاتصال المباشر، ويصلح لاختبارات مشاريع صغيرة موثوقة نسبياً. **لا يكفي لتشغيل سكربتات مستوردة قبل معالجة:** حصة القرص، وقيود واجهة Windows، وتحميل الكود الأصلي، ومسار تشغيل غير محزّم. ويبقى قيد لا تزيله هذه المعالجات: AppContainer يشارك نواة النظام مع المضيف، فثغرة نواة تتجاوزه.
