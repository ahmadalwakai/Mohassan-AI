# إشعارات مهام المحادثة في موحسن

عند إخفاء تبويب موحسن، يستطيع المتصفح إظهار إشعار نظام للتشغيل المسجّل في المحادثة. بعد إغلاق التبويب أو المتصفح، يستطيع اشتراك Web Push استقبال الإشعار إذا كان المتصفح والنظام يدعمان التسليم بعد الإغلاق. الضغط على الإشعار يفتح المحادثة ويعرض حالتها الحالية. تبقى قراءة الصورة المتزامنة ضمن طلب HTTP الحالي. [خطة التطوير، القسم 6.3](MOHASSAN-DEVELOPMENT-PLAN-2026-11-22.md#63-الإشعارات)

## عقد الحمولة

ترسل القناتان كائن JSON وفق `NotificationPayload` في [packages/contracts/src/notifications.ts](../packages/contracts/src/notifications.ts).

| الحقل | القيمة |
| --- | --- |
| `kind` | `task_completed` «اكتملت المهمة»، أو `needs_you` «تحتاجك خطوة»، أو `task_failed` «تعذّر الإكمال». يشمل `needs_you` الموافقة والإدخال والخطوة اليدوية. |
| `taskId` | معرّف UUID للتشغيل، يُستخدم لمنع التكرار والتحقق من ملكية الإشعار. يستخدم اختبار الإرسال معرّفًا مؤقتًا. |
| `conversationId` | معرّف UUID للتوجيه إلى `/?conversation=<conversationId>`. في اختبار الإرسال تكون القيمة `null` ويفتح الإشعار الصفحة الرئيسة. |
| `conversationTitle` | عنوان المحادثة حتى 100 خانة. يُحذف الحقل عند تفعيل إخفاء العنوان، ويغيب دائمًا من اختبار الإرسال. |

```json
{
  "kind": "needs_you",
  "taskId": "0d4d4d67-b9af-4f10-baab-7737478cbc14",
  "conversationId": "ffd04f3a-fd55-4397-90f1-79ad16d79130",
  "conversationTitle": "إعداد الحساب"
}
```

يعرض النظام العبارة العربية المحددة لـ `kind` والعنوان إن توفر. الحمولة لا تحتوي الرسائل أو الردود أو الأسئلة أو الأسباب أو بيانات الدخول. قد يتكوّن عنوان المحادثة من بداية الطلب الأول، لذا يزيل خيار «إخفاء عنوان المحادثة» هذا الجزء من شاشة القفل. المعرّفات مخصّصة للتوجيه والتحقق، ويتطلب جلب المحادثة جلسة مصادقًا عليها وملكية الحساب لها.

## قواعد التسليم

- يسجل الخادم النتيجة مع تغيير حالة تشغيل المحادثة. تتاح بعد مهلة ثانيتين لترجيح `needs_you` إذا وصلت نتيجتان قبل التسليم. يبقى التشغيل نفسه عند متابعة السؤال أو الموافقة، فلا يصدر إشعار ثانٍ عند اكتماله. تُحجب الإجابة التي تكتمل خلال أقل من 20 ثانية إذا كان للحساب تبويب ظاهر وقت اكتمالها. عند تهيئة Web Push، يفحص المرسل مهلات تشغيل المحادثات المنقطعة دوريًا حتى يسجل إخفاقها عند غياب التبويبات.
- يرسل التبويب حالته عند تغيّرها وأثناء بقائه مفتوحًا، ويحاول إرسال إشارة الإغلاق. تنتهي إشارة وجوده خلال 25 ثانية عند انقطاعها. يستطيع التبويب المخفي حجز الإشعار عندما لا يوجد تبويب ظاهر للحساب. يبحث مرسل Web Push عن النتائج المتاحة تقريبًا كل ثانيتين، ولا يحجز نتيجة طالما يوجد تبويب نشط للحساب. تبقى النتيجة مؤهلة خمس دقائق من وقت تسجيلها.
- حجز النتيجة عملية ذرية في الخادم. يبدأ Web Push بالجهاز الأقل إخفاقًا مع تفضيل أحدث تسليم ناجح عند التعادل. يحذف اشتراك الجهاز عند `404` أو `410` ويحاول الجهاز التالي. يتوقف عند أول قبول من خدمة الدفع أو عند إخفاق لم يُحسم فيه التسليم. قد يؤدي انقطاع الخادم أو إغلاق التبويب بعد الحجز إلى فقدان الإشعار، ويحتفظ مزوّد الدفع بطلب الإرسال مدة تصل إلى خمس دقائق.
- يتحقق عامل الخدمة من ملكية كل إشعار Web Push بجلسة الحساب الحالية قبل إظهاره، بما في ذلك إشعار الاختبار. انتهاء الجلسة أو تعذّر الوصول للخادم وقت التحقق قد يمنع ظهوره. يحاول تسجيل الخروج إزالة اشتراك المتصفح الحالي، ويحتفظ إغلاق التبويب بالاشتراك. يُتحقق من المحادثة مرة أخرى عند فتحها.
- ساعات الهدوء اختيارية ولكل حساب. يُفسّر الخادم البداية والنهاية بصيغة `HH:mm` في منطقة زمنية من IANA مثل `Asia/Riyadh`. تبدأ فترة الهدوء عند وقت البداية وتنتهي عند وقت النهاية. يمكن أن تمتد عبر منتصف الليل، وتساوي الوقتين يعطّل الفترة. زر الاختبار طلب يدوي ويعمل خلال ساعات الهدوء.
- يعرض الويب دعوة الإذن مرة واحدة عند رصد مهمة في الخلفية تجاوزت 20 ثانية. فتح الصفحة لا يطلق طلب الإذن. يفتح الضغط على الدعوة مطالبة المتصفح لأن المتصفحات تتطلب إجراءً من المستخدم. عند الرفض تظهر إشارة هادئة في الإعدادات، ويمكن تعديل الإذن من إعدادات المتصفح نفسه.

## إعداد Web Push

1. ثبّت اعتماديات المستودع وشغّل الأمر التالي من جذره لإنشاء ملف بيئة جديد خاص. السكربت يرفض الكتابة فوق ملف موجود ولا يطبع المفاتيح.

   ```sh
   node apps/server/scripts/generate-vapid-keys.mjs .env.web-push.local
   ```

2. عيّن `WEB_PUSH_VAPID_SUBJECT` باستخدام عنوان اتصال `mailto:` أو عنوان اتصال HTTPS عام. أضف `WEB_PUSH_VAPID_PUBLIC_KEY` و`WEB_PUSH_VAPID_PRIVATE_KEY` و`WEB_PUSH_VAPID_SUBJECT` إلى بيئة عملية الخادم. استخدم `.env` للتطوير أو ملف البيئة الخاص بالخدمة في النشر. أمثلة المتغيرات في [`.env.example`](../.env.example) و[`scripts/cloud-linux/server.env.example`](../scripts/cloud-linux/server.env.example).
3. احفظ المفتاح الخاص خارج Git. حافظ على زوج المفاتيح نفسه عبر إعادة النشر والنسخ المتوازية. يتطلب تغيير الزوج إعادة اشتراك الأجهزة. يعمل إشعار التبويب المخفي حتى عند غياب إعداد VAPID.
4. استخدم HTTPS في النشر أو عنوان loopback معتمدًا كسياق آمن للتطوير المحلي. يُخدّم الويب `/notifications-sw.js` من نفس النطاق. بعد منح الإذن وتسجيل الجهاز، يظهر في «الإشعارات» داخل الإعدادات ويمكن إرسال اختبار له. تعكس نتيجة الاختبار قبول مزوّد Web Push للطلب.

## المسارات المصادق عليها

تُستخدم المسارات عبر نطاق الويب نفسه. يعمل كل طلب بصلاحية الحساب في الجلسة، ويشمل ذلك المالك والأعضاء. تعيد قائمة الأجهزة معرّف الجهاز واسمه وتاريخ إنشائه وآخر نجاح وعدّاد الإخفاقات. يُخزّن الخادم عنوان الاشتراك ومفاتيح التشفير ويستعملها للإرسال.

| الطريقة والمسار | الاستخدام |
| --- | --- |
| `GET /api/notifications/settings` | قراءة التفضيلات والأجهزة ومفتاح VAPID العام إن كان مهيأ. |
| `POST /api/notifications/settings` | حفظ `{ quietHours, hideTitle }`. يحمل `quietHours` الحقول `{ start, end, timeZone }` أو القيمة `null`. يعيد الإعدادات المحدثة. |
| `POST /api/notifications/subscribe` | تسجيل `{ endpoint, keys: { p256dh, auth }, label }` وإرجاع `{ device }`. يُرفض عنوان الدفع المسجل لحساب مختلف. |
| `DELETE /api/notifications/devices/:id` | إزالة الجهاز من حساب الجلسة وإرجاع `{ removed }`. |
| `POST /api/notifications/test` | إرسال اختبار عربي بلا عنوان أو محادثة وإرجاع `{ delivered }` بقيمة صفر أو واحد. |
| `POST /api/notifications/sync` | تسجيل حالة التبويب `{ tabId, state }` حيث الحالة `visible` أو `hidden` أو `closed`. يعيد `{ backgroundTask, pending }`. |
| `POST /api/notifications/events/:id/claim` | حجز الإشعار لتبويب مخفي باستخدام `{ tabId }`. يعيد `{ notification }` أو `null` داخل الحقل. |
| `GET /api/notifications/events/:id` | تحقق عامل الخدمة من ملكية نتيجة Web Push أو اختبار الإرسال وفق معرّف قصير الصلاحية. يعيد `204` عند النجاح و`404` عند غياب نتيجة مطابقة للحساب. |

يدعم مرسل الويب اشتراكات Google FCM للمتصفحات، وMozilla Autopush، وApple Web Push، وMicrosoft WNS. يُستخدم بروتوكول Web Push مع تشفير `aes128gcm` ومفاتيح VAPID لهذه الاشتراكات.

## ما تحتاجه تطبيقات الهاتف لاحقًا

### وصلة على iPhone عبر APNs

- تفعيل Push Notifications لمعرّف التطبيق `com.ahmadalwakai.wasla` في حساب Apple، وإضافة `aps-environment` في ملف الصلاحيات وتحديث ملفات التوقيع. يحتاج المرسل إلى مفتاح APNs و`Key ID` و`Team ID` وموضوع التطبيق، مع البيئة المطابقة للتوقيع (`sandbox` أو `production`). يبقى مفتاح `.p8` لدى المرسل.
- طلب الإذن عند أول مهمة خلفية مؤهلة، وتسجيل رمز APNs عند إنشائه أو تغييره. تمرّ عملية التسجيل عبر جلسة وصلة الموثوقة والجسر إلى موحسن، ويربط الخادم الرمز بالحساب والجهاز والبيئة. يُزال الرمز عند إلغاء الثقة أو الاقتران أو عند إبلاغ APNs بأنه غير صالح.
- يحمل تنبيه APNs العبارة العربية من `kind`، ويرافقه `taskId` و`conversationId` لتوجيه التطبيق. يطبّق المرسل ساعات الهدوء للحساب، ويظل نص شاشة القفل عامًا وفق خطة وصلة. عند الضغط يُفتح مسار المحادثة ويجلب الحالة الحديثة عبر الجسر بعد التحقق من الجهاز والحساب. [خطة وصلة للآيفون، م7](WASLA-IPHONE-PLAN-2026-11-22.md#م7--المهام-والإشعارات-46-أيام)

### موحسن على Android عبر FCM

- ربط التطبيق `com.ahmadalwakai.wasla` بمشروع Firebase وإضافة مكتبة Firebase Messaging. إنشاء قناة إشعارات عربية، وطلب إذن `POST_NOTIFICATIONS` على Android 13 فأحدث عند أول مهمة خلفية مؤهلة. يحتاج المرسل إلى صلاحية Firebase Cloud Messaging HTTP v1 عبر اعتماد خدمة محفوظ على الخادم.
- تسجيل رمز FCM وتحديثه من `onNewToken` عبر جلسة الجسر الموثوقة، وربطه بالحساب والجهاز، وإزالته عند إلغاء الثقة أو عند رفض FCM الرمز باعتباره غير مسجل. ينقل FCM الحقول المشتركة والعبارة العربية، ويستخدم التطبيق معرّف المحادثة لاسترجاع حالتها من موحسن بعد التحقق من الجلسة.
- يعالج مسار الضغط الحالة الحالية حتى لو انتهت خطوة الموافقة أو الإدخال منذ الإرسال. تُراجع الصلاحية والحالة قبل أي إجراء حساس داخل المحادثة. [واجهة موحسن في تطبيق Android](../apps/android/README-AR.md)

ينبغي لمسار الهاتف استخدام سياسة التسليم نفسها وحجزًا مشتركًا مع الويب حتى تظل النتيجة الواحدة مؤهلة لإشعار واحد عبر جميع القنوات. رموز APNs وFCM الأصلية تحتاج تخزينًا ونقلًا خاصين بكل منصة. يتطلب اختبارها لاحقًا أجهزة فعلية، واختبارات الضغط أثناء الإغلاق، وتدوير الرمز، وإلغاء الثقة، والفصل بين حسابات المالك والأعضاء.
