# المرحلة الخامسة — Next التفاعلي والجسر السحابي

طبقة التشغيل الكامل مبنية من ثلاثة أجزاء: `apps/sandbox-gateway` داخل Vercel، و`apps/server/src/studio-live.ts` في خدمة API، ولوحة `studio-live-panel.tsx` في الاستوديو. يظل عرض React الأولي داخل AppContainer متاحًا كما سبق؛ الموفر السحابي يضيف بناء Next وتشغيله وخدماته داخل microVM.

## الحالة المثبتة

- تم تنفيذ الجسر والعميل وواجهة التشغيل والإيقاف وحالة الجلسة واختيار العناصر وتمرير تفاعل Next.
- **7 اختبارات محلية ناجحة** في `tests/studio-live.test.ts`: HMAC ونسخة المصدر، والتقاط HTML/CSS وإيقاف الحوسبة بعد التقاط الأصل، وقدرة المعاينة وتخزين بصمتها فقط، وفصل رأس Host والـcookies والـOrigin، وحصر التحويلات، ومنع تكرار POST، وتفاعل فعلي واختيار مصدر في Chromium ضمن iframe opaque، وإلغاء المعاينة عند تغيير المصدر، والحالة غير المهيأة.
- تستخدم هذه الاختبارات transport محقونًا يمثل استجابة الجسر، مع خادم معاينة محلي ومتصفح حقيقيين. **لا تثبت تشغيل Vercel microVM فعليًا**.
- تفعيل الجسر السحابي الفعلي لم يثبت في هذه الجلسة: محاولات الوصول إلى Vercel أعادت403 وروابط التفويض الجديدة ظهرت منتهية فورًا. لا يوجد ادعاء بناء Next سحابي ناجح أو نشر إنتاجي ناجح بسبب مرور اختبارات fixture.

## تجهيز الجسر

1. ينشر `apps/sandbox-gateway` كمشروع Node/Next منفصل على Vercel، مع تمكين صلاحيات Vercel Sandbox للمشروع/الفريق الصحيح.
2. ينشأ سر خادم عشوائي بطول32 حرفًا على الأقل في `STUDIO_GATEWAY_SECRET`، بنفس القيمة في الجسر وخدمة Mohassan API. لا يرسل إلى الواجهة ولا إلى مصدر المشروع داخل VM.
3. يضبط `STUDIO_GATEWAY_URL` في خدمة API إلى مسار HTTPS الخاص بـ`/api/control` في نشر الجسر. يلزم أن يستطيع اتصال الخدمة الوصول إلى المسار؛ صفحة تسجيل دخول Vercel أو رابط مشاركة منتهي ليست اتصالًا صالحًا.
4. `STUDIO_PREVIEW_PORT` يختار منفذ المعاينة المحلي (الافتراضي5000). يظل `WEB_ORIGIN` أصل واجهة التطبيق المصرح له بتضمين المعاينة. خدمة العامل تبني عند الحاجة دون فتح منفذ معاينة؛ المنفذ يفتح عند تسجيل routes في خدمة API فقط.
5. قبل اعتبار الاتصال جاهزًا، يجرى تشغيل مشروع Next صغير فعليًا وتوثيق بناء ناجح وTTL ومنع الشبكة ونتيجة UI. لم يتم تجاوز هذه الخطوة بإعلان الجسر جاهزًا اعتمادًا على وجود متغيرات البيئة.

عند غياب إعداد الجسر تعرض اللوحة الحالة غير المهيأة وتعطل التشغيل. وجود عنوان وسر يتيح محاولة مصرحًا بها؛ فشل المصادقة أو البناء يظهر كفشل محفوظ، دون إعادة تشغيل حوسبة تلقائية.

## ما يجري داخل microVM

الجسر ينشئ VM مؤقتة باسم عشوائي وعمر عشر دقائق وvCPU واحد. في البداية لا يوجد مصدر المستخدم؛ يسمح فقط بمخزن npm لتنزيل إصدارات محددة من Next وReact وTypeScript، مع `--ignore-scripts` ودون تشغيل package scripts خاصة بالمشروع. بعد تجهيز الأدوات تتحول سياسة الشبكة إلى `deny-all`، ثم تدخل ملفات المصدر المعتمدة وتكوين Next الموثوق.

يشغّل الجسر بناء Next الفعلي ثم خادمًا على loopback داخل VM، دون منافذ VM عامة. كل طلب معاينة ينتقل من خدمة API إلى الجسر بتوقيع HMAC، ثم إلى خادم Next الداخلي. ملفات `package.json` وإعدادات بناء المشروع لا تنفذ مباشرة؛ يستخدم الموفر إصدارات الأدوات وتكوينًا ثابتًا تحت سيطرته. الاعتماديات الإضافية والأصول التي تتطلب تنزيلًا أثناء البناء تحتاج توسعة نطاق واعتماديات مقصودة، ولا تتحول تلقائيًا إلى إذن شبكة عام.

التقاط الأصل يحفظ HTML أوليًا وCSS الناتج من Next مع بصمات المصدر، ثم يوقف VM في `finally`. المصدر المحفوظ لا يحتوي مفتاح القدرة المؤقت. تفعيل جلسة تفاعلية عملية منفصلة صريحة؛ لا تبقي عملية التقاط أصل المراجعة حوسبة نشطة دون حاجة.

## قدرة المعاينة وفصل الأصل

- لكل تشغيل مفتاح عشوائي192bit لا يوجد في SQL إلا SHA-256 الخاص به، مع المالك والجلسة وإصدار المصدر والمهلة وحالة التشغيل. يحتفظ API بالمفتاح الخام في ذاكرة العملية فقط. عند إعادة تشغيل API تلغى حالات التشغيل القديمة وتحتاج تشغيلًا جديدًا؛ لا تستأنف الحوسبة المدفوعة تلقائيًا.
- رابط المعاينة المحلي `http://<cap>.localhost:5000/p/<cap>` يفصل اسم المضيف عن `127.0.0.1:3000`، ويعرض في iframe بـ`sandbox="allow-scripts"` دون `allow-same-origin` أو top-navigation أو popups أو downloads.
- يتحقق خادم المعاينة من اسم المضيف والمسار والقدرة والمدة وإصدار المصدر عند كل طلب. أي تغير للمصدر يجعل الرابط السابق410. التحويلات الخارجية أو المسارات التي تخرج من prefix القدرة مرفوضة.
- لا يمرر أي Cookie أو Authorization أو سر داخلي من جهاز المستخدم إلى مشروع VM، ولا يعيد Set-Cookie إلى متصفح التطبيق. يسمح CORS بالأصل opaque `null` فقط بعد التحقق من القدرة، وليس سياسة عامة على API.
- CSP يحصر scripts/styles والصور والخطوط والاتصال في أصل المعاينة، ويمنع الكائنات والإطارات الفرعية والعمال والنماذج الخارجية. يسمح بتضمين المعاينة من `WEB_ORIGIN` فقط.

### حدود عزل المتصفح

سياسة VM تمنع الشبكة عند تشغيل مصدر المشروع. iframe المستخدم حد مختلف: CSP وsandbox يمنعان وصوله إلى cookies التطبيق وDOM الواجهة والتنقل العلوي والموارد الخارجية المحددة. **لا يثبت ذلك منع التنقل الذاتي للـiframe عبر `location` إلى عنوان خارجي في كل متصفح**؛ توجيه Location الصادر من proxy نفسه محصور، لكن `navigate-to` ليس حدًا يمكن الاعتماد عليه في Chromium. منع جميع قنوات نقل المتصفح يتطلب متصفحًا مُدارًا ذا شبكة مقيّدة أو عرضًا بالبث، ولا يوصف هذا iframe بأنه AppContainer أو VM للمتصفح نفسه.

## التفاعل واختيار المصدر

في وضع التفاعل تعمل أحداث React وطلبات Next داخل VM. يضيف الجسر معرّف طلب عشوائيًا لكل fetch POST، وتحتفظ طبقة API بإيصال منع التكرار قبل عبور الجسر؛ المعرف نفسه مع جسم مختلف يرفض، والاستجابة المحفوظة تعاد عند وجودها دون تنفيذ ثانٍ. الرد غير المحسوم لا يعاد تنفيذه تلقائيًا.

في وضع الاختيار لا ينفذ النقر فعل المشروع. يتحقق الجسر من معرف مصدر معروف وفريد ونوع العنصر، وترجع رسالة محدودة بـnonce وإصدار المصدر. تستقبلها اللوحة فقط من نافذة iframe نفسها ومن أصل opaque مطابق، ثم تربطها بخريطة مصدر الخادم. JavaScript المشروع داخل iframe يستطيع نظريًا إنشاء رسالة اختيار؛ **الاختيار ليس صلاحية كتابة**. الحفظ فعل مالك مستقل يعيد اشتقاق المصدر ويتحقق من النسخة والملكية، ولا يقبل مسارًا أو موضع كتابة يرسله المشروع.

## الاستمرار والإيقاف

تشغيل واحد نشط للمالك، وحتى300 طلب داخل جلسة المعاينة. التشغيل يبدأ202 وحالته محفوظة `building/active/failed/revoked/stale/expired`؛ تحديث الواجهة يستعيد حالته دون بدء VM أخرى. الإيقاف أو تغير المصدر يلغي القدرة ويطلب إيقاف VM بأفضل جهد؛ TTL السحابي يبقى حدًا نهائيًا إن تعذر الاتصال. إغلاق عامل بناء مستقل لا يلغي معاينات API النشطة؛ الإغلاق يمس الموارد التي تملكها نسخة التحكم نفسها فقط.

الاختبار السحابي الحي، وصلاحية اتصال Vercel، ودليل شبكة microVM في البيئة الفعلية، وتكاليفها وحدود الفريق، تبقى نقاط تحقق لازمة قبل إعلان هذا الموفر عاملًا لدى المستخدم.
