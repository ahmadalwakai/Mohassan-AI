# المرحلة السابعة — ذاكرة موثقة ومهارات قابلة للقياس

الحالة: تنفيذ محلي متصل بقاعدة SQL والواجهة العربية، بتاريخ 2026-11-04. الوحدة لا تدعي تعلّم نموذج عام أو قياس ذكاء ذاتي. التحسن المقاس يخص نوع مهارة تصريحي محدد؛ الأدلة والمدة والملكية ظاهرة لكل ذاكرة.

## ما يعمل

- ست طبقات: working وepisodic وsemantic وprocedural وfailure وpreference. تتبع كل ملاحظة مالكًا وإصدارًا ومصدرًا وبصمة وتاريخ مشاهدة وانتهاء. المصدر اليدوي يبقى user_asserted بقيمة ثقة وصفية0.5؛ ربطه بمهمة لا يرقّيه إلى حقيقة مثبتة. القيمة1 في task_observed تخص واقعة تسجيل حالة المهمة فقط، ولا تصدّق تلقائيًا ما كتبه النموذج في ملخصها.
- استيراد نتائج المهام النهائية من SQL تلقائيًا عند قراءة الذاكرة أو البحث أو طلب سياق، مع معرف المهمة وآخر حدث. يسجل الفشل في failure والنتائج الأخرى في episodic؛ القراءة محدودة بآخر80 مهمة، والتكرار لا يولد ذاكرة مكررة. الملخص المسجل منسوب لنتيجته، وليس حقيقة عامة أو مهارة نشطة.
- استرجاع نصي lexical-v1: ترشيح المالك والطبقة والمدة وحالة المصادر، ثم ترتيب كلمات العنوان والمحتوى. لا embeddings أو طلب نموذج خفي. ذاكرة العمل المرتبطة بمهمة لا تسترجع لمهمة أخرى. context يعيد حتى5 عناصر، والنص1200 حرف لكل عنصر، ومجموع JSON لا يتجاوز9000 حرف مع استشهادات المصدر. جميع النصوص بيانات غير موثوقة، ولا تمنح نطاقات أدوات أو صلاحيات.
- سياق التخطيط يستدعي أيضًا حتى3 مهارات مفعّلة ومقاسة ويضيف اقتراحات قوائم الفحص مع معرف النسخة وبصمة قواعدها. بذلك تؤثر المهارة التي اختبرها المستخدم ووافق عليها في سياق الخطة التالية؛ اقتراحاتها تبقى proposal_only ولا تشغّل أدوات أو توسّع صلاحيات.
- انتهاء الذاكرة يستبعدها فور القراءة، ولا يحتاج مهمة purge. مدة المراجعة الافتراضية: يوم لذاكرة العمل،90 يومًا للخبرات والتعثرات،180 يومًا للمعرفة،365 يومًا للإجراءات والتفضيلات؛ يمكن تحديد يوم آخر من الواجهة. التصحيح يكوّن إصدارًا جديدًا ويستبدل السابق؛ الطلب القديم لا يكتب فوقه. الإلغاء يوقف الاسترجاع. الحذف الصريح من الواجهة يحذف المحتوى وجميع إصداراته، مع سجل تدقيق محدود دون نسخ المحتوى.
- التغذية الراجعة تفرق task_correction وpreference وbenchmark_evidence. التصحيح يبقى في المهمة؛ الملاحظة من نوع preference لا تصبح تفضيلًا مستمرًا إلا مع persistPreference=true واختيار المستخدم الصريح. مفتاح submissionKey يمنع تكرار الحفظ ويكشف إعادة استعمال المفتاح لمدخلات مختلفة.

## نوع المهارة المنفذ وحد الثقة

نوع المهارة `checklist-router` مجموعة قواعد JSON محدودة: كلمات دالة، وتصنيف diagnostic/plan/coding/research، وقائمة فحص من scope/evidence/approval/verification/rollback. التنفيذ يستعمل مفسر بيانات محدودًا؛ لا eval أو JavaScript أو shell أو imports أو شبكة أو إجراءات خارجية. حتى بعد التفعيل يعيد `executionAllowed:false` و`scope:'proposal_only'`، فلا يتحول نجاح المهارة إلى تفويض لتنفيذ مهمة.

دورة النسخة:

`candidate → sandbox_tested → benchmarked → موافقة صريحة → active → revoked`

الاختبار المعزول هنا اختبار مفسر البيانات المحدود، وليس ادعاء AppContainer أو VM. ينفذ فعلًا مجموعة تدريب مثبتة مستقلة عن مدخلات المرشح، ويسجل نجاح ضوابطها. القياس التالي يعيد التقييم على مجموعة التدريب وعينة holdout منفصلة، مع suite/checklist-router-v1 وبصمة manifest وعدد الحالات والوقت ونتائج كل حالة. المجموع8 حالات، ونصفها holdout؛ هذه عينة صغيرة معلنة لهذا النوع من القواعد.

المعيار: safety=100% وholdout≥85% وعدم تراجع حالة نجح فيها الأساس، مع candidateScore≥baselineScore. الأساس مصنف بسيط ثابت، وتعرض الواجهة نتيجة الأساس والمرشح والعينة والتراجعات. المرشح الضعيف الذي يختار plan دائمًا يجتاز سلامة القواعد لكنه يفشل holdout؛ لا يتفعل. لا قبول لـJavaScript كنوع مهارة، ولا يسمح للمستخدم بتوريد درجاته أو تغيير حالات القياس عبر API.

التفعيل يتطلب expectedRevision وموافقة approve=true ومعرف تقييم benchmark ناجح للنسخة نفسها وبصمة manifest نفسها، مع مصادر مملوكة سارية. القواعد غير قابلة للتعديل بعد إنشاء النسخة؛ تعديلها ينشئ إصدارًا جديدًا يحتاج اختباره وقياسه وموافقته. تفعيل نسخة أخرى من العائلة يوقف النسخة السابقة، ويمكن استعادة إصدار أقدم سبق قياسه بموافقة جديدة. الإلغاء يوقف استدعاء الإصدار فورًا للطلبات الجديدة. لا ترقية تلقائية بسبب عدد الذكريات أو تقييم مستخدم واحد.

## الواجهة والعقود

`MemoryWorkspace` يعرض الذكريات ومصادرها والبحث والتصحيح والإصدارات والإلغاء والحذف الصريح، ونموذج التغذية الراجعة، وإنشاء مرشح مهارة واختباره وقياسه والموافقة عليه وتجربته وإلغائه. حالات التحميل والخطأ والفراغ والانقطاع واضحة؛ الانقطاع يعطل الكتابة ويحفظ آخر عرض في ذاكرة الصفحة. CSS مستقل ومتجاوب للكمبيوتر والهاتف.

| المسار | العملية |
|---|---|
| GET `/api/memory` | الملاحظات والمهارات والتغذية الراجعة ومقاييس المهام والتوكنات المعروفة |
| POST `/api/memory/search` | بحث موثق مع استبعاد المنتهي |
| POST `/api/memory/items` | ملاحظة يدوية منسوبة لمصدرها |
| GET `/api/memory/items/:id` | الملاحظة وآخر20 إصدارًا |
| POST `/api/memory/items/:id/correct` | تصحيح مع expectedVersion وسبب |
| POST `/api/memory/items/:id/revoke` | إلغاء الاسترجاع |
| POST `/api/memory/items/:id/delete` | حذف صريح لكل إصدارات المحتوى |
| POST `/api/memory/sync` | توثيق أحدث نتائج المهام دون تكرار |
| POST `/api/memory/feedback` | ملاحظة مصنفة مع موافقة مستقلة للتفضيل المستمر |
| POST `/api/memory/skills` | مرشح أو إصدار جديد بقواعد ثابتة |
| POST `/api/memory/skills/:id/test` | اختبار مفسر البيانات ومجموعة التدريب |
| POST `/api/memory/skills/:id/benchmark` | مقارنة الأساس والمرشح على تدريب وholdout |
| POST `/api/memory/skills/:id/activate` | تفعيل صريح مرتبط بالتقييم والبصمة والإصدار |
| POST `/api/memory/skills/:id/revoke` | إلغاء إصدار |
| POST `/api/memory/skills/:id/run` | اقتراح قائمة فحص من إصدار مفعّل فقط |

كل مسار يحتاج جلسة المالك، وسر وكيل التطبيق، وOrigin موثوقًا للكتابة عبر حواجز الخدمة العامة. كل استعلام مرئي مقيد بالمالك. بيانات الاعتماد ذات الصيغ المعروفة مرفوضة في الإدخال اليدوي، ومنقحة من مقتطفات المهام التلقائية؛ لا تُقرأ ملفات أسرار أو بيانات اعتماد من القرص.

## التخزين والفحص

ترحيل `007_memory_learning_v1` ينشئ memory_evidence وmemory_items وmemory_provenance وmemory_feedback وmemory_audit وmemory_skill_families وmemory_skill_versions وmemory_skill_evaluations. إدخال المرشحين يقفل صف المالك، والتصحيح يقفل الإصدار، والتفعيل يقفل عائلة المهارة وإصدارها. لا مفتاح نموذج أو credentials إضافية مطلوبة. سقف الإدخال اليدوي2000 إصدار ذاكرة و100 إصدار مهارة للمالك؛ حصة القرص والاحتفاظ الإنتاجي تبقى ضمن المرحلة11.

نجح الاختبار المركز `packages/memory/src/memory.test.ts`: ثمانية اختبارات تشمل الطبقات الست والملكية والمصادر والأسرار والانتهاء والتصحيح والإلغاء والحذف والإصدارات القديمة ونتائج Runtime فعلية والتغذية الراجعة وسياق المهمة والمقاييس، ثم القياس والموافقة ورفض المرشح الضعيف وربط التقييم بالبصمة والإصدار والاستعادة والإلغاء. رحلة `tests/e2e/memory.spec.ts` تنفذ الواجهة مع مهمة تشخيص حقيقية داخل بيانات المتصفح المؤقتة؛ تسجل نتيجة التجميع النهائي في IMPLEMENTATION-STATUS.
