## نقل الملفات BR8

المسار موصول من لوحة المتصفح في المحادثة إلى API المالك، ثم SQL وAgentBrowser والنقل الشبكي المثبت بعنوان IP. لا توجد أداة نموذج تمنح صلاحية ملف أو توافق عليها أو تخرجه من الحجر.

- يختار المالك ملفًا من جهازه، وحقل ملف مرصودًا في الصفحة. تُحفظ منحة لعشر دقائق مرتبطة بالمالك والمحادثة والحساب وبصمة الصفحة وملفات تعريف الارتباط والوجهة وحقول النموذج وبصمة الملف.
- الموافقة والإرسال إجراء منفصل، يستهلك المنحة ذريًا مرة واحدة في SQL. يعاد فحص الملكية وحالة المحادثة والمنحة والصفحة والقيم بعد DNS وقبل النقل.
- الرفع يدعم نموذج `POST multipart/form-data` قياسيًا إلى أصل الصفحة نفسه، بملف واحد وحقول حالية محدودة. تُرسل القيم المخفية مثل CSRF كما رُصدت؛ تُحفظ بصمتها دون كشفها في مراجعة المنحة. حقول الدخول الحساسة وأزرار تغيير الوجهة ونماذج الرفع البرمجية غير مدعومة.
- النقل ينشئ جسم multipart في الخادم؛ لا يوضع محتوى الملف في عنصر الصفحة ولا يصبح قابلًا للقراءة من JavaScript الموقع. لا تقبل API مسار نظام ملفات أو وجهة يختلقها النموذج.
- التنزيل يبدأ من رابط مرصود يوافق عليه المالك. يسمح بتحويلات داخل أصل الرابط فقط مع فحص الشبكة لكل طلب ومنع دورات إعادة الطلب. تُرسل ملفات تعريف ارتباط الحساب فقط إلى أصل الصفحة، ولا ترسل إلى أصل مختلف.
- الأنواع الحالية: نص UTF-8 وMarkdown وCSV وJSON وPNG، بحد **512 KiB** للملف. PNG يحتاج توقيعًا وCRC وفكًا بنيويًا، وأبعادًا موجبة لا تتجاوز 8192 لكل محور و4 ملايين بكسل. تقبل أسماء الملفات العربية مع منع محارف المسار والتحكم.
- التنزيل المقبول يبقى `quarantined`. يعاد فحص بايتاته وبصمته قبل تحرير صريح ثم عند إخراجه. الإخراج `attachment` و`application/octet-stream` مع `nosniff` وCSP sandbox، واسم مولّد آمن لا يتبع اسم الموقع.
- انتهاء الصلاحية يمنع الوصول فورًا؛ كنس عند بدء الخدمة وكل دقيقة يحذف المحتوى المنتهي. عشر منح معلقة كحد أقصى وعشرون خانة حية للمالك، بما فيها حجوزات التنزيل. حذف المحادثة يحذف سجلات الملفات التابعة لها.
- الإلغاء مستقل عن انتظار النقل في الواجهة. يوقف الطلب الجاري ويمنع اعتماد الرد المتأخر. إرسال بدأ بالفعل ثم انقطع أو أُلغي يبقى `unknown` ولا يُعاد تلقائيًا. الاستعادة بعد إعادة التشغيل تحول المنح `dispatching` إلى `unknown` وتمسح المحتوى.
- `responded` يعني وصول استجابة نقل فقط؛ لا يثبت حفظ الملف أو نجاح هدف تجاري داخل الموقع. عند غياب الرد يُحفظ طلب مراجعة الجلسة.

**حدود الشريحة:** ليست فحص برامج ضارة، ولا دعمًا لـOCR أو PDF ثنائي أو ZIP أو ملفات تنفيذية أو upload widgets. استخراج نص PDF في المعرفة مسار مستقل، ولا يطهر أصل الملف الثنائي. هذه الحدود معروضة للمستخدم قبل النقل.

### قبول قراءة MDN بعد فصل رفض الطلب الخلفي

كان `network.validate` يرفض POST خارج النطاق قبل وصوله إلى `decideEffect`، فيسجل رفضه باعتباره فشل أمر فتح المستند. أما POST الخلفي داخل النطاق فكان يُرفض أصلًا بواسطة سياسة الأثر دون إفساد القراءة. عولج هذا الفرق الضيق في تصنيف النتيجة، وبقي `route.abort` قبل أي نقل خارجي.

الاستثناء محصور في أمر `open` بلا منحة إرسال أو إرسال سابق أو أثر معلق، وطلب خلفي غير ملاحي، وخطأ `BROWSER_SCOPE_DENIED` تحديدًا عند فحص النطاق. لا يشمل POST الملاحة أو الإطارات، أو نقر/كتابة النموذج، أو الطلب الموافق عليه، أو فشل التفويض والاتصال. لم يُعدّل `network.ts` أو `effect-policy.ts` لإنجاح MDN، ولم يُسمح بمصدر telemetry أو يتغير معيار قبول الصفحة.

اختبارا Chromium وHTTP المحليان في `tests/browser-background-write.test.ts` أثبتا الفرق قبل وبعد الإصلاح: النسخة السابقة أخفقت في قبول القراءة، وبعد الإصلاح نجح الاختباران. يُتحقق من ظهور «Telemetry blocked» في الوثيقة، وصفر وصول إلى خادم telemetry وصفر إرسال أثر؛ وتبقى محاولات POST الملاحة والنقر مرفوضة. طلب POST الموافق عليه الذي يحاول تحويل 307 خارج النطاق يرسل مرة واحدة فقط، ويبقى `AGENT_EFFECT_UNKNOWN` دون وصول إلى وجهة التحويل.

نجحت المجموعة المركزة بعد التعديل **61/61 في ستة ملفات، دون تجاوز**: الأثر، وأمان الشبكة، ونقل الملفات، والاستعادة، وانحدار المتصفح، والاختبار الجديد. التقرير `artifacts/browser-background-write-final.json`؛ تقرير الإخفاق السابق `browser-background-write-before.json` محفوظ، ولا تجمع أعداد هذه المجموعة مع المجموعات المتداخلة أعلاه.
