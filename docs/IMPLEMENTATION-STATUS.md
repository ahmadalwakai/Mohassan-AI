## ربط الأدوات بالمساعد — 5 نوفمبر 2026

صار المساعد في المحادثة يصل إلى الذاكرة والبرمجة والاستوديو وجهاز Windows. كل أداة تستدعي وحدتها الحالية عبر `apps/server/src/assistant/tools.ts`، فتبقى الملكية والموافقة والعزل والتحقق في مكانها، ولا يوجد مسار تنفيذ ثانٍ.

| الأداة | ما تفعله | الضابط |
|---|---|---|
| `memory_search` | بحث في الذاكرة | النتائج بيانات غير موثوقة |
| `memory_save` | حفظ حقيقة مع كلمات المالك نفسها | لا تعمل إلا إذا طلب المالك الحفظ في رسالته، ورفض بيانات الاعتماد، وحد 3 مرات لكل طلب |

- **الرفض والإيقاف:** رفض الموافقة أو إيقاف المحادثة أو انتهاء مهلتها يلغي المهمة التي لم تُعتمد، وإيقاف المحادثة يلغي العمل الجاري.
- **منع التكرار:** تكرار نداء مطابق لأدوات الذاكرة والمهام يُرفض في الكود دون تنفيذ. الخطوة التالية لأداة عمل تذهب إلى النموذج القوي.
- **Windows:** يحفظ الخادم بصمة آخر جلسة استخدمت المحادثة في الذاكرة فقط. لا يُنشئ المساعد منحة بنفسه؛ إن لم توجد منحة يطلب من المالك إنشاءها. يُعاد تحديد العنصر على أحدث صورة قبل كل إدخال. يبقى حد المنحة 120 ثانية، ويُسجل كل وصول في سجل التدقيق.
- **التحقق:** `tests/assistant-tools.test.ts` يشغّل التطبيق الحقيقي مع Runtime والذاكرة ومسارات Windows بنقل محاكى. `npm run assistant:check -- --live` يستخدم Groq الحقيقي وAppContainer الفعلي وقاعدة ومشروعًا مؤقتين. نجحت 3 من 3 جولات متتالية: حفظ واسترجاع، وموافقة، ثم إصلاح معزول حقيقي بنتيجة `ready_for_review`، ودون دمج، ودون تغيير المصدر.
- **ما كشفته الجولات الحية وأُصلح:** تكرار الحفظ، وحفظ الحقيقة بلغة لا يجدها البحث، ورد نهائي فارغ، وفشل JSON داخل حقل النص، ومحاولة فتح مسار المشروع كموقع، وسؤال المالك عن أسماء الملفات.
- **لم يُثبت:** لم تُجرَّب أدوات Windows مع المرافق الأصلي أو جهاز حقيقي، ولا `studio_change` مع نموذج حي. لا يستطيع المساعد تسجيل مشروع جديد أو حذف ذاكرة. البحث في الذاكرة لفظي. مهلة 120 ثانية قد تقطع مهام Windows الطويلة.
- **خلل مفتوح:** أعاد Groq خطأ 400 (`REQUEST_REJECTED`) للنموذج السريع `openai/gpt-oss-20b` في جولات حية قبل نقل ما بعد أدوات العمل إلى النموذج القوي، ولم يُعرف سببه الدقيق لأن نص الخطأ لا يُحفظ. قد يبقى هذا في خطوات المتصفح التي تستخدم النموذج السريع، ولا يُعاد الطلب آليًا وفق قاعدة R5.

## التحقق الحالي — إصلاح Skill Engine، 5 نوفمبر 2026

هذا القسم يحل محل ادعاءات الاكتمال في السجل الأقدم أدناه. العمل محلي، ولم تُجر ترحيلات على قاعدة البيانات المضبوطة في بيئة التشغيل أو اتصالات إلى مزود حي أو نشر. الترحيلات الجديدة اختُبرت على قواعد PGlite قابلة للتخلص منها فقط.

- **M12 مقبول في نطاق المرشحين غير التنفيذيين:** توليد عبر محول النموذج الحالي، وإيصال دائم قبل الاتصال، ومفتاح تكرار وملكية محددة المدة، وحفظ الاستهلاك المتأخر دون نشر مرشح بعد فقدان الملكية. يدخل الناتج الحجر عبر مخزن الاستيراد المشترك؛ الترقية والتراجع يمران ببوابة دورة الحياة الإلزامية التي تثبت نسب المرشح والفحص والمقارنة المستقلة والموافقة الصريحة. واجهة مراجعة المصدر تعيد نصًا متحقق البصمة فقط. تحقق ختامي: 133/133 في ستة ملفات، 38.73 ثانية، وفحصا TypeScript ناجحان. التوليد اختُبر بردود محاكية عبر المحول الحقيقي؛ لا إثبات جودة نموذج حي أو جودة دلالية عامة. ترقية التنفيذيات محجوبة.

- **M13 مقبول في نطاق الرحلات المختبرة:** مكتبة Chakra متصلة بالعقود الفعلية، ومراجعة مصدر وصلاحيات ونسخ وتركيب وتشغيل وأدلة وقياس وForge وتطور القدرات. نجحت الجولة النهائية 9/9 خلال 200.61 ثانية، بلا إخفاق أو تجاوز أو flaky، وتشمل ثلاث رحلات للمكتبة وستًا للميزات السابقة. الهاتف 360px بلا تمرير أفقي في الحالات المختبرة؛ 64 عينة تباين مكتبية و67 للهاتف اجتازت الحد (أدنى 5.15:1 و5.92:1). هذه فحوص وصول محددة وليست شهادة WCAG شاملة. كُشف وأُصلح خطأ webpack، وسباقات عرض/موافقة، وتباين النصوص، وتحويل دخول POST→303→GET على العنوان نفسه مع إبقاء منع الإعادة. نجح إصلاح الدخول في 43 اختبارًا وتحقق مستقل من 10 حالات. لم تُغير بوابات التنفيذيات.

- **R1/R2:** فشل فحص الأمان عند تجاوز سقف النتائج، مع تجميع الشدة مستقلاً عن العرض، ومنع التفعيل بفحص قديم. صُحح اتجاه اعتماد المهارات والتحقق من المدخلات والمخرجات. أُضيف تسلسل ذري لحصة الاستيراد ورفض زيادة رقم النسخة خارج حدود العقد.
- **R3/R6/R7:** تحقّق الإرسال عند حد طلب المتصفح، وموافقات ذات استعمال واحد مرتبطة بالوجهة والطريقة والحمولة والمشاهدة. ملكية المحادثة وleases وfencing وإيصالات قبل الآثار تمنع الاستئناف المكرر؛ الأثر المجهول لا يُعاد تلقائيًا. لا ادعاء تنفيذ خارجي exactly-once.
- **R4/R5:** تحليل مدد Groq، وتصنيف fallback موحد؛ إعادة واحدة على نموذج مهيأ فقط بعد إثبات استخدام صفري وتأخير مسموح. التأخير الأصلي وبيانات الخطأ محفوظة؛ الرد المدفوع أو المبهم لا يُعاد.
- **M1–M3:** جرى التحقق من نطاق السجل والاستيراد والأمان والتركيب في 175 اختبارًا. هذا ليس إثبات عزل سكربتات أو تزامن PostgreSQL متعدد الاتصالات.
- **M4:** سياق التعليمات مفعّل اختيارياً عبر `SKILL_ENGINE_ENABLED`، وافتراضيًا معطل. اختيار metadata محدود، وتحميل تدريجي مع بصمات ومصادر وحد سياق، وإعادة التحقق من الإلغاء في كل خطوة. يعمل عبر API وChat وCognitive Runtime وworker؛ لا يمنح أدوات أو صلاحيات. 70 اختبارًا مستهدفًا نجح، مع مقارنة مستقلة تثبت بقاء الموجهات القديمة مطابقة عند تعطيل الميزة.
- **M0 مقبول بعد إصلاح الفحص:** ينتظر الفحص الآن حكم نظام التشغيل على كل واجهة بدل مؤقت 1.5 ثانية، ولم تتغير قائمة النتائج المقبولة. مجموعة القبول 53/53 بلا تجاوز، و`available:true`، وتعمل رحلة Coding Lab وعرض React داخل AppContainer فعليًا. التفاصيل في [ISOLATION.md](ISOLATION.md). المهارات التنفيذية تبقى محجوبة بسبب G2 وG5 وG8.
- **M5 مقبول لنطاق الأدوات المهيأة:** جدولة عبر Runtime الحالي، ومدخلات/نواتج مثبتة، وموافقات مستقلة لكل مهمة فرعية، وGateway يعيد فحص البصمة والمنح، وأدلة وصور سابقة وقفل مورد محفوظ في SQL. نجحت رحلتان عبر API والمتصفح الحقيقي والمجلد المؤقت: مهارة واحدة ثم تركيب مهارتين لقراءة صفحة محلية وكتابة تقرير ببصمة متحققة. مسارات التشغيل والحالة والأدلة والإلغاء منفذة، بما فيها إلغاء تشغيل قديم عند تعطيل الميزة.

- **M6 مقبول ضمن النطاق المختبر:** تعافٍ للتحقق فقط من الإيصالات المؤكدة، وإيقاف الآثار المجهولة دون إعادة، ومحاولات محدودة بموافقات مستقلة وتأجيل محفوظ، وقاطع دائرة SQL، وتراجع مصرح عن كتابة مؤكدة فقط. خمس حالات قتل عامل فعلية، بينها قراءة موقع محلي ثم استكمال تقرير بعد الإيقاف، أثبتت عدم تكرار الآثار المؤكدة. فشل التحقق من ملف تغير لاحقًا، وبقي قفل الأثر المجهول محفوظًا. 16 اختبار تراجع و33 اختبار Runtime/متصفح/تعافٍ اجتازت الجولات المركزة؛ الأعداد تتداخل مع المجموعة العامة ولا تُجمع معها.

## المساعد العام — سجل تاريخي، 5 نوفمبر 2026

استُبدلت المحادثة المقيدة بمساعد عام وواجهة محادثة بسيطة. الأقسام السابقة بقيت خلف قائمة الحساب ← «الأدوات المتقدمة». ما يلي عن المحادثة في الأقسام الأقدم أصبح تاريخيًا.

- **المتصفح:** `packages/browser/src/agent-browser.ts` متصفح عادي تعمل فيه المواقع الحديثة، بملف تعريف محفوظ في `.data/browser-profile`، مع منع العناوين الداخلية والخاصة. المتصفح المقيد القديم ما زال يخدم قسم «المتصفح والبحث» المتقدم.
- **العقل:** `apps/server/src/assistant/brain.ts` يقرر دون نموذج ما يمكن تقريره: فتح المواقع، ورفض ملفات الارتباط، وتمييز الدخول والكود والتحقق البشري. يختار النموذج القوي للتخطيط والتعافي ومراجعة الرد، والسريع للخطوات المعتادة، وينتقل بين النماذج عند نفاد الحصة (8000 توكن/دقيقة لكل نموذج).
- **الدخول:** `apps/server/src/assistant/vault.ts` يبقي البيانات في الذاكرة فقط، لموقع واحد، ولعشر دقائق كحد أقصى، ويمسحها عند اكتمال الدخول أو انتهاء المهمة.
- **الموافقة:** قبل الدفع والحذف والإرسال والنشر وتغيير إنفاق الإعلانات. تعتمد على اسم الزر وتقدير النموذج، فقد تفوتها حالات نادرة، مثل زر باسم غير معتاد أو إرسال بمفتاح Enter.

### غير محسوم أو غير منفذ

- **عزل AppContainer:** فشل إثبات توفره في جلسة التحقق، فتعطلت اختبارات البرمجة المعزولة. حزمة `packages/sandbox` مطابقة للنسخة الاحتياطية، والسبب الدقيق لم يُحدد. يلزم فحصه قبل استخدام «مشاريع البرمجة».
- **دخول حقيقي كامل:** لم يُجرب بحساب فعلي. قد ترفض Google وبعض المواقع المتصفح الآلي؛ عندها يطلب المساعد أن تسجل الدخول بنفسك من لوحة المتصفح.
- **التدخل اليدوي:** مسار النقر على الصورة والكتابة (CAPTCHA) مكتوب، لكن لم تغطه رحلة آلية.
- **النشر على Vercel:** لم يُنفذ. يحتاج الويب على Vercel إلى رابط HTTPS يصل إلى الخدمة والمتصفح على جهازك.
- **ربط بقية الوحدات بالمساعد:** رُبطت الذاكرة والبرمجة والاستوديو وWindows لاحقًا (القسم الأول أعلاه). وأصبح يقرأ حساب Google Ads ويحفظ المعاينات عبر الـ API الرسمي؛ لم يُربط حساب حقيقي بعد، والتفاصيل والحدود في `docs/GOOGLE-ADS.md`.

## حالة المحادثة السابقة — سجل تاريخي

أصبحت «المحادثة» نقطة البداية بعد الدخول. يكتب المالك طلبه باللغة الطبيعية دون اختيار قدرة أو مستوى استقلالية، ثم يختار نموذج Groq في الخادم خطوات فعلية من أدوات المتصفح المحددة. هذا مسار تنسيق بالنموذج متعدد الأدوار، وليس تحويل الطلب إلى تشخيص ثابت أو تشغيل خطة عامة لجميع وحدات المنصة. أقسام المهام والبرمجة والاستوديو والذاكرة وWindows تبقى متاحة بصورة مستقلة.

- محادثة يمينًا ومتصفح يسارًا على الكمبيوتر، وترتيب عمودي على الهاتف. يعرض المتصفح عنوان الصفحة ورابطها ووقت مشاهدتها وصورتها الفعلية المحمية بالمصادقة، مع آخر الخطوات. تُقرأ حالة المتابعة كل 800 مللي ثانية أثناء التنفيذ فقط، وتتوقف المتابعة الدورية عند اكتمال الدور أو انتظار المالك؛ هذه مشاهدات بعد الخطوات وليست بث فيديو مستمرًا.
- أدوات محددة لفتح صفحة وقراءتها، واتباع رابط ظاهر، وملء حقل ظاهر غير حساس، والبحث بمصادر عامة، وطلب الضغط على زر أو إرسال نموذج. لا يرسل النموذج أو الواجهة JavaScript أو محددات حرة للتنفيذ. المحتوى المقروء من الصفحة يبقى بيانات غير موثوقة ولا يمنح صلاحيات.
- سؤال بخيارين أو ثلاثة يظهر في نافذة صغيرة غير حاجبة؛ يوضع الخيار المقترح أولًا عند وجوده، ولا يُختار تلقائيًا. يمكن إخفاء السؤال وإعادته. الأفعال التي تحتاج إرسالًا أو تغييرًا تعرض موافقة صريحة على الوجهة والطريقة والقيم المحددة، ولا يجيز سؤال عام إرسال نموذج من وراء الواجهة.
- الرسائل والاختيارات والأحداث والمشاهدات وإيصالات استخدام النموذج محفوظة في SQL ومقيدة بالمالك. قائمة المحادثات تعيد فتح السجل، وتستعاد المحادثة المختارة بعد إعادة التحميل. يوقف زر «إيقاف» المتابعة ويغلق جلسة المتصفح ويلغي الموافقات المعلقة؛ لا يعكس إرسالًا سبق اعتماده وتنفيذه.
- يتطلب كل دور متصفح جديد فتحًا أو قراءة حديثة قبل التفاعل مع حقول الصفحة أو أزرارها أو الاعتماد على محتواها. واعتماد رد يدعي تنفيذًا أو تحليلًا يحتاج معرفات المشاهدات الفعلية التي عُرضت على النموذج في الدور الحالي؛ لا يكفي سجل مشاهدة من دور سابق. وطلب اللقطة يحتاج دليل صورة فعلية. تعذر أداة أو صورة لا يتحول إلى ادعاء نجاح، ولا يُحتسب التشخيص دليلًا على فتح موقع. تبقى السجلات التشخيصية القديمة محفوظة مع تنبيه «اكتمل التشخيص فقط» عند انطباقه.
- سجل استخدام مستقل لكل خطوة نموذج، مع حجب البيانات الحساسة وحدود للسياق والوقت والمخرجات. عند تعطل العملية تُوقف الأدوار الجارية للمراجعة، ولا يتكرر طلب مدفوع أو فعل خارجي غير محسوم تلقائيًا. حفظ السجل لا يعني استئناف تنفيذ غير مراقب بعد إعادة التشغيل.
- سياق الصفحة مختصر دون تكرار المشاهدة كاملة في نتائج الأدوات، ويعاد استخدام الصفحة المفتوحة عند تطابق الطلب بدل إنشاء جلسة مكررة. يسمح الخادم بانتظار `Retry-After` وإعادة واحدة فقط داخل الدور بعد رفض HTTP 429 صريح ثبت أن استخدامه صفر؛ الانتظار قابل للإيقاف ويبقى ضمن مهلة الدور وحد الخطوات. رفض آخر أو خطأ شبكة ذو نتيجة غير معلومة لا يُعاد تلقائيًا.
- لمسار Google Ads العام أربعة أصول قراءة محددة: `https://ads.google.com` و`https://consent.google.com` و`https://www.gstatic.com` و`https://business.google.com`. ثبت التحويل من `https://ads.google.com/home/` إلى صفحة الهبوط `https://business.google.com/us/google-ads` بعد الاختيار الصريح في صفحة الموافقة. لا يضيف هذا نطاق حسابات Google أو يجيز تسجيل الدخول أو الضغط على بدء حملة.

حدود الشريحة: ثماني خطوات للدور، مهلة متابعة أربع دقائق، ومخرجات نموذج حتى 768 توكن لكل خطوة. لا اتصال بحساب Google Ads أو صلاحيات حملات أو إنفاق أو OAuth؛ فتح صفحته العامة لا يثبت الدخول أو إدارة الإعلانات. قد تظهر موافقة ملفات ارتباط أو صفحة دخول أو تحقق بشري تحتاج قرار المالك. حقول كلمات المرور والدفع والأسرار خارج أدوات الملء الحالية. المحادثة لا تشغّل أوامر نظام ولا أدوات برمجة عامة، ولا تمثل اكتمال العقل التنفيذي أو بقية الخطة الإنتاجية.

### الفحص الحي للمحادثة وGoogle Ads — نجاح الرحلة النهائية

صُحح رفض Groq الأول بـHTTP 400: القرار المطلوب مستند JSON يراجعه المنفذ، وليس استدعاء أدوات أصليًا من المزود؛ وُضح هذا للنموذج مع عقد منظم متوافق. أثبتت المحاولة التالية فتح Google وقراءة صفحة موافقة ملفات الارتباط، ثم أعاق حد الحصة المتاح للحساب (8000 توكن/دقيقة في تلك المحاولة) متابعة الدور. عولج تكرار السياق والفتح وأضيف الانتظار المحدود المذكور أعلاه.

وصل مسار حي لاحق بعد اختيار رفض ملفات الارتباط صراحةً إلى صفحة Google Ads العامة الفعلية على `business.google.com`. حُفظ إرسال الاختيار ومشاهدته. ثم حاول النموذج فعلًا إضافيًا غير لازم بدل إنهاء طلب الفتح؛ صُححت قاعدة الإنهاء لتجيب فور تحقق الصفحة واللقطة المطلوبتين. نجح طلب Groq حي مستقل على سياق هبوط مكافئ بـHTTP 200 وإجابة تستشهد بمعرف المشاهدة، ثم نجحت الرحلة النظيفة الكاملة من الواجهة بالمصدر النهائي.

الدليل النهائي في 5 نوفمبر 2026: طلب المالك الطبيعي لفتح Google Ads وعرض اللقطة → سؤال الاختيار عند 01:12:41.983 → اختيار الرفض صراحةً عند 01:12:48.738 → وصول الصفحة العامة بعنوان `Reach Customers Across YouTube & Search - Google Ads` على `business.google.com` → رد المساعد عند 01:13:01.075: «تم فتح موقع Google Ads وعرض لقطة للصفحة بنجاح.» انتهت المحادثة بحالة `idle` و`error:null`. تحقق مسؤول التجميع من الحالة عبر API ومن الواجهة الفعلية، وحُفظت اللقطة الأحدث في `artifacts/google-ads-chat-browser.jpg`. هذه الرحلة تستخدم Groq وGoogle الفعليين، وتختلف عن فحوص المزود المحقون وصفحة الاختبار المحلية.

النتيجة غير المحسومة لإرسال من محاولة أقدم تبقى غير محسومة في سجلها، ولا تُحوّل إلى نجاح بسبب الرحلة اللاحقة الناجحة. يثبت هذا الفحص فتح الصفحة العامة وإتمام الاختيار المصرح وعرض صورتها والرد المستند إليها؛ لا يثبت الدخول إلى حساب Google Ads أو إدارة إعلاناته أو تشغيل بقية وحدات المنصة عبر المحادثة.

## سجل المرحلة الثالثة

- ربط Groq فعليًا بمفتاح خادم محلي مستبعد من Git. النماذج الافتراضية `openai/gpt-oss-20b` للأهداف المحدودة و`openai/gpt-oss-120b` للأهداف الأعقد، مع تفسير سبب الاختيار. التوجيه حاليًا بقواعد محددة؛ لا يدعي مقارنة أداء متعلمة أو قياس جودة شاملًا.

- قدرة `plan.draft` تستخدم نفس المهمة والموافقة والإلغاء وfencing. خطتها محفوظة في `task_plan_steps` و`task_plan_dependencies` بحالة planned. لا تشغّل أدوات الخطة أو تحقق هدف المستخدم تلقائيًا.

- سجل `model_runs` يحفظ الطلب المنطقي ومحاولته والتوكنات المعروفة وكون النتيجة اعتمدت. callback فاشل ذو usage معروف يسجل failed مع إبقاء الاستخدام؛ unknown لا يعني صفر تكلفة. ledger منطقي وقد يشمل fallback داخليًا محدودًا بعد رفض HTTP واضح، ولا يمثل حسابًا ماليًا بالفواتير.
- لا إعادة تلقائية لطلب تخطيط مدفوع غير محسوم بعد خطأ أو تعطل عامل، حتى scoped؛ ينتظر تفويضًا جديدًا. shadow لا يستدعي Groq ولا ينشئ إيصال نموذج.
- اتصال Groq يعرض configured/verified/error ويستند إلى طلب حقيقي وتاريخ، وصحة لا تتجاوز 24 ساعة ولا تقبل تاريخًا مستقبليًا. تغيير المفتاح أو النموذج يبطل الدليل القديم. فتح اللوحة لا يستدعي المزود.
- واجهة عربية لإنشاء خطة ومراجعة معاييرها وتبعياتها وصلاحياتها وأسئلتها واستهلاكها. الاكتمال يعرض «اكتمل إعداد الخطة»، وshadow يعرض «اكتمل الاقتراح»؛ لا يزعم تنفيذ الهدف.

### دليل الاتصال والتخطيط الحي

نفّذ مسؤول التجميع `npm run ai:check -- --live` باستخدام المفتاح المقدم وإعدادات فعلية، دون مزود محقون. أثبت `/models` توفر النموذجين، ثم نجح اختبار توليد منظم صغير وحُفظ دليل الاتصال في SQL المستخدم. اختُبرت رحلة منفصلة كاملة: إعداد مالك اختبار في ذاكرة SQL معزولة → دخول → إنشاء مهمة assisted → موافقة → Groq فعلي → فاحص مستقل → حفظ الخطة وخطواتها وإيصالها.

النتيجة الحية: النموذج `openai/gpt-oss-20b`، **1216 توكن إدخال و694 توكن إخراج، وثلاث خطوات محفوظة**، `verification.scope=structure_and_policy` و`executionAllowed=false`. التقرير المنقح في `artifacts/live-plan.json`. لم يُنشأ مالك أو مهمة تجريبية في بيانات المستخدم الدائمة؛ حفظ الاتصال وحده في مخزنه الحقيقي. لا يعني هذا الفحص الواحد قياس جودة شاملًا أو تفعيل كل قدرات العقل.

## المنفذ في الشريحة الحالية

- Monorepo باستخدام npm workspaces وTypeScript؛ تطبيق Next.js، وخدمة Node دائمة، وحزم عقود وتخزين وتشغيل وموائم مزود.
- عقود Zod مشتركة للمهمة وحالاتها وأحداثها والقدرات ولقطة مساحة العمل؛ إدخال محدود لا يقبل أوامر shell أو قدرات خارج التشخيص والتخطيط النصي المعتمدين.
- مصادقة Better Auth فعلية مع SQL، وإنشاء مالك واحد برمز إعداد محلي، ومنع التسجيل العام. مسار الإعداد المحلي معطل في إعداد الإنتاج.
- خدمة Fastify مع مصادقة الجلسات، وسر اتصال داخلي للوكيل، وتقييد Origin لطلبات التعديل، وحدود حجم ومعدل، وردود لا تخزن بيانات المالك مؤقتًا.
- مخزن PGlite محلي يمكن حفظه على القرص، مع قفل يمنع فتح المجلد ذاته من عمليتين؛ Kysely ومسار اتصال PostgreSQL للإنتاج وترحيلات SQL ذات إصدارات.
- Runtime واحد: سجل قدرات، مهام محفوظة، مفاتيح idempotency، أحداث متسلسلة، موافقات محدودة، إلغاء، leases ومحاولات محدودة، وتحقق منفصل من النتائج.
- أداة `system.diagnostic` فعلية للقراءة فقط. scoped يشغل الفحص الآمن؛ assisted ينتظر موافقة؛ shadow ينتج خطة محاكاة دون تشغيل أداة الفحص.
- استعادة حجز إعداد محلي يتيم عند بدء الخدمة تحت ملكية التخزين المحلي الحصرية، مع الحفاظ على المالك والجلسة بعد نجاح الإعداد وإعادة التشغيل.
- واجهة عربية RTL للوحة والمهام والقدرات والتكاملات، ووكيل API من الأصل نفسه؛ اجتازت تجربة متصفح فعلية على عرض الكمبيوتر والهاتف.
- موائم Groq نصي بحدود زمن وحجم وتوكنات وأخطاء منقحة. رُبط بالتخطيط واختبر حيًا في المرحلة الثالثة أعلاه؛ أداة التشخيص لا تستدعي أي نموذج.

نفذ مسؤول التجميع الفحوص التالية عند إنجاز المرحلتين الأولى والثانية؛ أرقام المرحلة الثالثة الأحدث أعلاه:

| الفحص | النتيجة والدليل |
|---|---|
| `npm run typecheck` | نجاح TypeScript في الخدمة والحزم والاختبارات والويب |
| `npm test` | **37 اختبارًا ناجحًا في 4 ملفات**: API عدد 17، استعادة الإعداد 1، Runtime عدد 15، موائم Groq عدد 4 |
| `npm run build` | بناء Next ناجح؛ الصفحة الرئيسية ثابتة ووكيل API ديناميكي |
| `npm run test:e2e` | **اختبار متصفح متكامل ناجح** باستخدام Chromium وSQL وخدمة HTTP وNext فعليين، دون طلبات نموذج أو حسابات خارجية |
| التشغيل المحلي | `npm run dev`؛ خدمة API على 4000 وواجهة على 3000، ورد HTTP 200 من الصفحة الرئيسية |

تجربة المتصفح: إنشاء مالك → جلسة مصادق عليها → مهمة assisted → موافقة → تشغيل وفحص مستقل ونتيجة وأحداث → إعادة تحميل مع بقاء البيانات → إلغاء مهمة أخرى → فقد الاتصال وتعطيل الأفعال ثم التعافي → تنقل هاتف بعرض 390px دون تمرير أفقي → خروج ودخول مجددًا إلى اللوحة. لم تسجل التجربة أخطاء JavaScript غير معالجة. استُخدم مخزن مؤقت ومالك اختبار، ولم يُنشأ حساب المستخدم الحقيقي.

اختبارات Runtime تثبت: idempotency متزامن، عزل المالك، الموافقة المحددة بالمحاولة، انتهاء/إلغاء التفويض حتى عند اعتماد النتيجة، fencing، استعادة lease آمنة، الإلغاء التعاوني، حدود المحاولات، رفض مخرجات لا تحقق معايير الفاحص، shadow دون استدعاء الأداة، حفظ SQL بعد الإغلاق وإعادة الفتح ومنع مشاركة مخزن التطوير.

فُحصت لقطتا `artifacts/workspace-desktop.png` و`artifacts/workspace-mobile.png` بصريًا بعد اكتمال حركات الواجهة. هذه صور لبيئة الاختبار وليست بيانات المستخدم. جميع المخرجات والأسرار المحلية مستبعدة من Git.

خلال التحقق صُححت إعادة استخدام الموافقة بعد محاولة فاشلة، وإمكان اعتماد نتيجة بعد إلغاء التفويض، وتعليق إعداد المالك بعد توقف الخدمة، وبقاء قسم الهاتف مفتوحًا بعد تسجيل الخروج. تغطيها اختبارات الحالة النهائية.

## المتطلبات المتبقية قبل الإنتاج

- دور SQL محدود وإدارة ترحيلات وحمل واستعادة إنتاجية؛ الاتصال الفعلي بـNeon وفحص claims/fencing عبر poolين اجتازا التحقق في المرحلة الرابعة.
- إعداد استضافة دائمة لخدمة API والعامل، وأسرار إنتاج وHTTPS ونطاق ونشر الويب.
- فحوص حمل وتعافٍ ونسخ احتياطي وفق RPO/RTO متفق عليهما؛ البناء والمتصفح المحليان اجتازا التحقق، ويعاد اختبارهما ضد بيئة الإنتاج عند إعدادها.
- نقل بيانات اعتماد Groq إلى إعداد نشر آمن عند النشر، وبيانات التكاملات الخارجية عند تنفيذ مراحلها؛ الاتصال المحلي بـGroq تحقق فعليًا، ولا يثبت نجاحًا في بيئة نشر غير مهيأة.
- سياسة احتفاظ وميزانية وvault وتنبيهات تشغيلية معتمدة.
