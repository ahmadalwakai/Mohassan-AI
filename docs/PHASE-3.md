# المرحلة الثالثة — ربط Groq ونواة الذكاء والتخطيط

تاريخ البدء: 2026-11-04. تنفيذ تدريجي فوق Foundation وRuntime القائمين. هذا المستند يحدد نطاق المرحلة ومعايير قبولها، ويُحدّث بالنتائج الفعلية قبل التسليم.

## النطاق

طلب المستخدم يجيز حفظ مفتاح Groq محليًا ضمن `.env` المستبعد من Git، واختبار الاتصال، واستدعاء النموذج لإنشاء خطط. لا يوسع ذلك صلاحيات أدوات البرمجة أو المتصفح أو الإعلانات أو الأجهزة. لا تعرض قيمة المفتاح أو تحفظ في حدث أو نتيجة أو bundle للمتصفح.

الخطة الناتجة تصف هدفًا ومعايير نجاح وأدلة متوقعة وقيودًا وافتراضات وخطوات وتبعيات وأسئلة وعدم يقين. اكتمال مهمة `plan.draft` يعني إعداد خطة واجتيازها فحص البنية والسياسة؛ لا يعني تنفيذ هدفها أو إثبات صحة كل افتراض.

## تدفق التنفيذ

1. المستخدم يختار تشخيصًا أو تخطيطًا، ويكتب الهدف وحدود النجاح.
2. نفس عقود المهمة والمصادقة ومنع التكرار تحفظ الطلب. assisted يتوقف للموافقة؛ scoped يسمح بالطلب النصي المحدد إلى Groq؛ shadow لا يتصل بالنموذج.
3. Goal Compiler وModel Router يحددان السياق والنموذج من قائمة مضبوطة في إعداد الخادم. لا يختار المستخدم endpoint خارجيًا ولا مفتاحًا في JSON.
4. الموائم يطلب JSON Schema strict دون أدوات، بحد زمن وحجم استجابة وتوكنات. يعزل الأسرار ويخفي أي مفتاح يظهر في نص الطلب/الرد.
5. Strategy Planner يتحقق من مراجع الخطوات، ويرفض التكرار والحلقات والتبعيات المفقودة، وينتج مجموعات خطوات مستقلة. هذه مجموعات تخطيط فقط، ولا يُشغّل DAG أدوات في هذه المرحلة.
6. Policy يشتق الصلاحيات وحالة توفر كل قدرة من السجل الموثوق، ولا يعتمد منح النموذج. المستقبل غير المتاح يظل معروضًا كخطوة محجوبة.
7. Uncertainty Gate يحدد الحاجة لتوضيح؛ درجة ثقة النموذج وصف ذاتي وليست دليلًا تجريبيًا.
8. verifier مستقل يعيد فحص البنية والسياسة. تُحفظ الخطة وخطواتها وأحداثها تحت fencing وبعد إعادة فحص التفويض. سجل طلب النموذج يحتفظ بالاستخدام المعروف حتى لو مُنع اعتماد الخطة.

## حدود الطلب والتعافي

- حد الهدف 4000 حرف؛ سياق محدود، ومخرجات حتى 4096 توكن لكل استدعاء. بحد أقصى استدعاءين عند رفض HTTP 429/503 واضح. لا ادعاء أن حد المخرجات يمثل حدًا دقيقًا لتكلفة المدخلات قبل الإرسال.
- لا fallback عند غموض انقطاع الشبكة أو المهلة أو رد مبتور أو خطة غير صالحة؛ الخطأ يظهر للمستخدم دون حلقة إصلاح مكلفة.
- بعد تعطل عامل التخطيط أو فشل طلبه، لا يكرر scoped طلبًا مدفوعًا آليًا. يلزم تفويض جديد، مع إظهار أن استخدام الطلب السابق قد يكون غير محسوم.
- lease التخطيط الافتراضية 90 ثانية؛ كل رد متأخر من عامل فقد التفويض أو الـlease لا يعتمد نتيجة المهمة.
- نتيجة النموذج وإيصال الاستخدام عمليتان مختلفتان: استهلاك التوكنات لا يثبت نجاح الخطة، وإلغاء المهمة لا يلغي بالضرورة استهلاك مزود خارجي بدأ بالفعل.

## القبول

| المجال | معيار القبول |
|---|---|
| Groq حي | فحص نماذج فعلي ثم استجابة منظمة ناجحة؛ configured منفصل عن verified ويحمل تاريخًا؛ لا طلبات تلقائية عند فتح اللوحة |
| العقود | هدف ومعايير وخطوات typed، وحدود أطوال وأعداد، ورفض unknown fields والبيانات المبتورة |
| التوجيه | اختيار سريع/أعمق مفسر حسب تعقيد الطلب، fallback محدود، ورفض provider غير المجهز |
| التخطيط | DAG بلا حلقات أو مراجع مفقودة، مجموعات كاملة دون تكرار، وصلاحيات مشتقة من registry |
| التفويض | assisted لا يستدعي النموذج قبل الموافقة؛ shadow لا يستدعيه مطلقًا؛ إلغاء/انتهاء موافقة يمنع commit |
| الديمومة | SQL يحتفظ بالخطوات وإيصالات النموذج؛ restart لا يكرر استدعاءً غير محسوم |
| الأمان | API مصادق وOrigin، لا مفتاح في HTTP أو logs أو events أو المصدر المتتبع؛ الاختبارات لا تستخدم المفتاح الحقيقي |
| الواجهة | إنشاء خطة وعرض أهدافها ومعاييرها وتبعياتها وأسئلتها واستهلاكها؛ حالات خطأ/انقطاع وحالة Groq واضحة |
| التحقق | typecheck + اختبارات Core/Provider/SQL/API + build + متصفح + مهمة تخطيط حية معزولة عن بيانات المالك |

## نتائج التحقق الفعلية

فحص `/models` الحي أثبت توفر `openai/gpt-oss-20b` و`openai/gpt-oss-120b` لحساب المفتاح وقت الفحص. ثم نجح `npm run ai:check -- --live`: اتصال وتوليد منظم صغير، ثم رحلة مصادقة ومهمة وموافقة وطلب Groq وفحص وحفظ خطوات وإيصال في SQL معزول. نتيجة الخطة الحية: `openai/gpt-oss-20b`، 1216 توكن إدخال و694 إخراج، وثلاث خطوات محفوظة دون تنفيذ أدوات. التقرير المنقح `artifacts/live-plan.json`؛ دليل الاتصال في مخزن المستخدم SQL، أما مالك الاختبار ومهمته فداخل الذاكرة فقط.

نجح TypeScript وبناء Next، و102 اختبارًا في 9 ملفات، وتجربة Chromium موسعة على الكمبيوتر والهاتف تشمل التخطيط والموافقة والنتيجة وshadow وإعادة التحميل. الاختبارات الآلية تستخدم ردودًا محقونة ولا تستدعي المفتاح الحقيقي. الفحص الحي منفصل وصريح، ولا يدعي benchmark جودة أو جاهزية إنتاجية أو تنفيذ هدف الخطة.

راجِع `IMPLEMENTATION-STATUS.md` لنتيجة التجميع وحدود باقي المراحل، و`API-SPEC.md` و`DATA-MODEL.md` للعقود والجداول الجديدة.
