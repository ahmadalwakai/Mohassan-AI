# المرحلة الخامسة — التعديل باللغة والصورة والمراجعة قبل التطبيق

تاريخ التنفيذ: 2026-11-04. هذا المستند يصف مسار `studio.change` فوق الاستوديو الحالي. تشغيل Next العام وموفره البعيد موثقان بصورة مستقلة؛ نجاح هذا المسار لا يعني توفر حساب سحابي أو نشر مشروع تلقائيًا.

## دورة فعلية باستخدام محرك المهام المشترك

1. يختار المالك مشروع الاستوديو وإصداره، ويكتب وصفًا، ويمكنه إرفاق PNG أو JPEG. يتضمن `studioInput` معرف المشروع وrevision ومعرف العنصر والصورة اختياريًا. بصمة idempotency تشمل السياق كله، والإنشاء يتحقق من ملكية المشروع والصورة وإصدارهما.
2. `studio.change` قدرة عالية الأثر. assisted وscoped كلاهما يتوقفان عند `waiting_approval`. الموافقة العادية في Runtime تربط المالك والمهمة والمدخلات والإصدار والمحاولة والنطاق `studio:change` والمدة؛ لم ينشأ محرك موافقات آخر.
3. shadow يحاكي المسار فقط؛ لا طلب نموذج أو نقل صورة أو بناء أو Worktree أو توكنات. في التنفيذ الحقيقي تُنشأ نسخة Git أساسية وفرع Worktree داخل مجلد الخدمة الخاص، من نسخة SQL لا من المستودع الأصلي للمستخدم.
4. يقرأ الخادم ملفات موجودة ومصرحًا بها. لا تعديل package/config/test أو أسرار، ولا إنشاء أو حذف ملفات. يرسل حتى5 ملفات وبحد سياق15000 حرف إلى نموذج نصي أو نموذج رؤية مجهز صراحةً. النص والصورة بيانات غير موثوقة، ولا تمنح أدوات أو صلاحيات. لا مفاتيح على الواجهة.
5. يسجل Runtime محاولة النموذج قبل الاتصال. بعد وصول الرد يحفظ إيصال الاستخدام فورًا قبل التحقق من JSON أو الاختبارات. الخادم يربط expectedHash بالنسخة الموثوقة؛ لا يطلب من النموذج نسخ بصمات. ترفض المسارات غير المصرح بها والتكرار والأسرار والإصدارات المختلفة.
6. يطبق المقترح في Worktree فقط. يحسب Git الفرق الفعلي ويتحقق من تطابق قائمة مساراته مع التعديلات المطلوبة، ثم يطلب من الاستوديو معاينة النسخة وفحصها. فشل البناء يحفظ فرقًا قابلًا للمراجعة بحالة failed، ويحافظ على المصدر والمعاينة السابقة.
7. يلتقط الاستوديو صورتين فعليتين من المستندين الآمنين داخل Chromium بلا JavaScript أو شبكة، بواجهة1024×768. يحفظ الصور مملوكة ومحددة المدة، ويحسب changedPixels/totalPixels/ratio. النسبة تقيس تغير الصورة، ولا تدعي جودة التصميم أو اكتمال سلوكه.
8. النجاح يحفظ checkpoint وفرعًا وإيصالًا خاصًا. فاحص مستقل يعيد قراءة ملفات النسخة وشجرة Git وblobs والفرق وHEAD الأساس ويقارنها بالإيصال وSQL. JSON canonical بمفاتيح مرتبة يحافظ على البصمات بعد إعادة ترتيب JSONB للمفاتيح.
9. Task completed يعني مقترحًا متحققًا وجاهزًا للمراجعة، و`applied:false`. تظهر الصورتان والفرق والفحوص والتوكنات ونقطة Git في تفاصيل المهمة. تطبيق المقترح زر منفصل، يحتاج ملكية ومهمة مكتملة ومقترحًا غير متغير وrevision مطابقًا. يغير الاستوديو نسخته وسجل التراجع وحالة المقترح في معاملة SQL واحدة؛ الإعادة تعيد إيصال التطبيق نفسه. لا merge أو push أو نشر للمستودع الأصلي.

## الصور والحدود

- الصورة المرجعية PNG/JPEG فقط، من32×32 إلى1600×1600، وحتى1MB بعد التنقيح. يفحص decoder الأبعاد والنوع، وينزع metadata أثناء الترميز. تحفظ الصورة في SQL الخاص حتى24 ساعة، وبحد20 صورة للمالك في النافذة؛ لا تُرسل إلى النموذج عند الرفع أو فتح الصفحة.
- يحتاج الإرفاق `GROQ_VISION_MODEL` متاحًا فعليًا للحساب. تعرض الواجهة حالة جاهزية الرؤية. غياب الإعداد يمنع الطلب البصري؛ لا يُدعى إرسال صورة عبر نموذج نصي. إدخال vision يستخدم المحتوى الفعلي للصورة في رسالة النموذج بعد الموافقة.
- المصدر حتى40 ملفًا نصيًا و128000 بايت؛ الملف حتى64000 بايت، ومجموع التغييرات64000 بايت، و5 ملفات تعديل، و4096 توكن إخراج. الردود والفروق والإيصالات محدودة الحجم.
- انتهت مهلة العامل أو ألغيت المهمة: لا يعتمد عامل فقد lease أو الموافقة النتيجة. يبقى إيصال الاستخدام المعروف، ولا يعاد طلب مدفوع تلقائيًا. وجود محاولة Worktree سابقة يمنع الكتابة فوقها ويحتاج مهمة جديدة بعد المراجعة.
- صور المقارنة المرجعية محفوظة سبعة أيام بحد80 صورة للمالك؛ مساراتها تحتاج الجلسة والملكية. لا URLs عامة أو تحميل ملفات خفي. حصة القرص العامة وأرشفة الإيصالات والاحتفاظ الإنتاجي ضمن المرحلة11.

## الملفات والعقود

`packages/studio-ai` يتولى سياسة الملفات وGit والإيصال وفحصه، و`apps/server/src/studio-ai.ts` يتولى المزود والصور وSQL والمسارات. `StudioAiPanel` ينشئ مهمة ذات نطاق واضح، و`StudioAiResult` يعرض المراجعة والتطبيق الصريح. `Runtime` يحتفظ بالموافقات والتوكنات والتعافي والفصل بين التنفيذ والتحقق.

| المسار | الأثر |
|---|---|
| GET `/api/studio/ai/status` | جاهزية النص والرؤية، دون طلب نموذج |
| POST `/api/studio/images` | حفظ صورة خاصة منقحة، دون إرسالها للنموذج |
| GET `/api/studio/images/:id` | قراءة صورة المالك فقط |
| POST `/api/tasks` مع capabilityId=`studio.change` | مهمة بموافقة Runtime ونطاق ثابت |
| GET `/api/studio/proposals/:id` | نتيجة مقترح مملوك وحالة تطبيقه |
| POST `/api/studio/proposals/:id/apply` | تطبيق صريح ذري عند مطابقة revision |
| GET `/api/studio/reviews/artifacts/:id` | صورة مقارنة مملوكة محددة الصلاحية |

الترحيل `007_studio_ai_input` يضيف `tasks.studio_input`، و`008_studio_ai_proposals` ينشئ الصور والمقترحات، و`009_studio_visual_reviews` يحفظ أدلة المقارنة. ترحيل الذاكرة له معرف مستقل رغم اشتراكه في رقم المرحلة.

## أدلة الاختبار

اختبارات Runtime تثبت الموافقة الإلزامية حتى scoped، وحماية ملكية المصدر وإصداره وبصمة idempotency، وshadow، وحفظ التوكنات عند فشل لاحق، ورفض فرق مزور وفشل المراجعة. اختبارات الخدمة تستخدم نموذج fixture معلنًا مع Git وSQL وChromium فعليين: تثبت roundtrip عبر JSONB، والصورتين والمقارنة، وبقاء المصدر حتى التطبيق الصريح، والتراجع، ورفض Worktree متغير، وفشل البناء، وملكية الصورة وربطها بطلب تمت الموافقة عليه. إثبات المزود الحي منفصل ولا يدخل CI أو الاختبارات المعتادة تلقائيًا.
