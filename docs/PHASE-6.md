# المرحلة السادسة — المتصفح والبحث بالمصادر

تنفيذ فعلي في `packages/browser` وواجهة «المتصفح والبحث». جلسة Chromium مستقلة لكل مورد، وقراءة وروابط وتمرير ومشاهدات محفوظة، وموافقة منفصلة للإرسال. البحث يعمل بمصادر قرئت فعليًا، ويحتفظ بروابطها وأوقات الوصول وبصماتها ومقتطفاتها.

## دورة المتصفح

1. يختار المالك عنوان HTTPS عامًا ونطاق أصول صريحًا، لمدة من5 إلى60 دقيقة. لكل مالك حتى6 جلسات مفتوحة، ولكل جلسة حتى50 مشاهدة. لا يستخدم المتصفح Chrome الشخصي أو ملفًا شخصيًا مشتركًا.
2. تنشأ BrowserContext جديدة بملفات تعريف ارتباط منفصلة، دون إذن تنزيل أو service workers أو نوافذ إضافية. تعرض الواجهة لقطة الصفحة والنص المقروء والروابط والنماذج وسجل الأحداث.
3. `navigate/read/click/scroll` أفعال محددة؛ النقر يقبل معرف رابط صادرًا من المشاهدة فقط. لا تستقبل API شيفرة JavaScript أو selector حرًا أو مسار ملف. كل فعل مرتبط بمعرف آخر مشاهدة، وأي تغير يرفض طلبًا قديمًا.
4. المشاهدة الأخيرة محفوظة في SQL؛ السجل يحفظ النص والروابط والتوقيت دون تكرار الصور الكبيرة. إعادة تحميل الواجهة تستعيد الجلسة نفسها. بعد إعادة تشغيل خدمة API تبقى الأدلة وتظهر الجلسة التشغيلية كغير متاحة؛ فتح عنوان ضمن النطاق يستأنف بسياق جديد دون افتراض استعادة cookies.
5. الإغلاق يلغي الموافقات المعلقة ويغلق السياق ويوقف نقل الشبكة الجاري. انتهاء التفويض يغلق السياق أيضًا، ولا تقبل API فعلًا جديدًا بعده.

## حد الشبكة

- HTTPS فقط ومنفذ443 في التشغيل العادي، دون userinfo أو `file:` أو روابط محلية. تُرفض العناوين الخاصة والمحلية وCGNAT وmetadata والعناوين المحجوزة وIPv4 غير المعتاد وIPv6 المضمّن/الانتقالي.
- تُحل جميع إجابات DNS قبل كل طلب؛ وجود إجابة خاصة ضمن سجل مختلط يرفض الطلب كله. يثبت اتصال Node على عنوان عام من الإجابات المفحوصة مع الاحتفاظ باسم TLS والتحقق من الشهادة. لا اعتماد على فحص اسم المضيف ثم ترك المتصفح يحل العنوان من جديد.
- كل طلب صفحة أو مورد يمر عبر `route.fulfill` وموفر HTTPS المقيّد. يعاد فحص كل تحويل والوجهة ضمن الأصول المصرح بها. Chromium خلف proxy محلي يرفض أي نقل لا يعالجه المسار الموثوق، مع تعطيل DNS المباشر وQUIC وWebSocket ومنع WebRTC غير المار عبر proxy.
- لا يُمرر إلى الموقع سر الخدمة أو cookies التطبيق. ما يُمرر من cookies يخص BrowserContext نفسها فقط. الطلب حتى2MB، ومع مهلة اتصال ونقل، وحد200 طلب لكل جلسة. التنزيلات والترميزات المضغوطة غير المدعومة ترفض بدل تحميل بلا حدود.
- `testOrigins` حقن من إعداد الخادم داخل الاختبارات فقط؛ ليس حقلًا في API، ويرفض التطبيق إتاحته في وضع الإنتاج. يسمح بخادم fixture محلي دون فتح الشبكة الداخلية للمستخدم.

## الموافقة والإرسال

النموذج المرصود يحدد وجهة وطريقة وحقولًا ثابتة وبصمة. يختار المستخدم القيم ثم يطلب موافقة لمرة واحدة، ويراجع الصفحة والوجهة والقيم ووقت الانتهاء قبل «موافقة وإرسال مرة واحدة». لا تُقبل كلمات مرور أو حقول دفع أو ملفات ضمن هذه الجلسة.

تحفظ الموافقة في SQL ببصمة JSON قانونية مستقرة أمام ترتيب مفاتيح JSONB، ومعرف المشاهدة والمالك والجلسة وانتهاء بعد5 دقائق. يستهلك الخادم الموافقة تحت قفل قبل الإرسال. نقل POST يحتاج تصريحًا إضافيًا مطابقًا للرابط والطريقة والقيم الفعلية، ولا تسمح نقرات القراءة بإرسال نموذج. تعديل الصفحة أو إعادة استخدام الموافقة أو إرسال JSON إضافي يرفض العملية. يمكن رفض الموافقة أو إغلاق الجلسة لإلغائها.

تعود استجابة HTTP ومشاهدة مستقلة للنتيجة؛ لا يوصف ذلك وحده بإتمام حجز أو عملية تجارية. عند غموض الرد تحفظ الحالة `unknown`، وتبقى الموافقة مستهلكة، ولا توجد إعادة إرسال تلقائية. يلزم قراءة الصفحة والتحقق من أثرها قبل إنشاء طلب جديد.

## البحث وحفظ الأدلة

- البحث الافتراضي Bing RSS، مع DuckDuckGo HTML عند تعذر الأول؛ كلاهما صفحات عامة فعلية دون مفتاح API. إذا منعت الخدمة الوصول أو طلبت CAPTCHA يظهر فشل صريح ويمكن تقديم روابط مصادر مباشرة. جرى فحص الموفر العام حيًا وإرجاع روابط HTTPS فعلية.
- لكل بحث حتى5 مصادر وعمق1 أو2، مع نطاق مواقع اختياري. المصدر يعاد جلبه بحد الشبكة نفسه؛ لا يتحول snippet محرك البحث إلى مصدر مقروء.
- التقرير يحفظ `url/title/accessedAt/contentHash/text/quote` لكل مصدر. المقتطف حتى22 كلمة من النص الفعلي، و`claims` مقتطفات مرتبطة بمعرفات مصادر، دون استنتاجات نموذج مختلقة.
- المقارنة ترصد اختلافات محتملة في الأرقام أو النفي بين مقتطفات متقاربة، وتبقي المصدرين ظاهرين بحالة `needs_review`. هي مساعدة مراجعة لغوية، وليست حكمًا آليًا بصحة مصدر أو إثباتًا لغياب تعارض حين لا تظهر إشارة.
- يبدأ البحث بمعرف محفوظ وحالة `running` ويستمر عند مغادرة صفحة الويب، ثم يستعاد التقرير من SQL. يدعم الإيقاف، وحتى بحثين متزامنين للمالك. مهلة اعتماد5 دقائق تحول عملًا مهجورًا إلى فشل قابل للمراجعة؛ لا تختلق نتيجة بعد انقطاع الخدمة.
- المحتوى الخارجي بيانات غير موثوقة: لا يصبح تعليمات للأدوات أو إذن إرسال أو مدخلات سرية. كل ناتج يعرض كنص، والصلاحيات مشتقة من جلسة المالك ونطاقه.

## API المنفذة

| الطريقة والمسار | السلوك |
|---|---|
| GET `/api/browser/workspace` | جلسات وأبحاث المالك المختصرة |
| POST `/api/browser/sessions` | إنشاء نطاق ومدة جلسة مستقلة |
| GET `/api/browser/sessions/:id` | آخر مشاهدة وسجل وموافقات مملوكة |
| GET `/api/browser/sessions/:id/observations` | سجل مرقم بحد50 و`afterSequence` |
| POST `/api/browser/sessions/:id/actions` | navigate/read/click/scroll مع معرف المشاهدة |
| POST `/api/browser/sessions/:id/prepare-submit` | طلب موافقة للحقول والوجهة الثابتة |
| POST `/api/browser/sessions/:id/approvals/:approvalId/approve` | استهلاك وإرسال مرة واحدة |
| POST `/api/browser/sessions/:id/approvals/:approvalId/revoke` | رفض موافقة معلقة |
| POST `/api/browser/sessions/:id/close` | إغلاق وإلغاء الصلاحيات المعلقة |
| POST `/api/research/runs` | بدء بحث محفوظ في الخلفية |
| GET `/api/research/runs/:id` و`/:id/report` | حالة وتقرير بأدلة المصدر |
| POST `/api/research/runs/:id/cancel` | إيقاف قراءة البحث |

كل مسار يحتاج جلسة المالك والسر الداخلي من وكيل Next، وكل POST يحتاج Origin الموثوق. مورد غير مملوك يعيد404، بما فيه الحالة التي توجد فيها عملية أخرى تحت قفل المورد. المخطط يرحل من `migrateBrowser()` ذرّيًا تحت قفل مخطط التطبيق.

## التحقق

`tests/browser-security.test.ts` و`tests/browser-control.test.ts` و`tests/browser-api.test.ts`: **15 اختبارًا ناجحًا**، تشمل Chromium حقيقيًا وHTTP fixture مستقلًا، وDNS rebinding وسجلات مختلطة، وفصل cookies، ومنع POST الصفحة، والإرسال المعتمد الفعلي مرة واحدة، والتعارض والتراجع عن الموافقة، وإلغاء الجلسة، وحفظ تقارير حقيقية والملكية وإيقاف البحث واستعادة lease مهجورة. اختبار API يمر عبر المصادقة وroutes المسجلة، واختبار منفصل يشغل Node مع `--import tsx` كما في خدمة التطوير كي لا تخفي بيئة Vitest اختلافات تحويل callbacks الخاصة بالمتصفح.

`tests/e2e/browser.spec.ts` يغطي الرحلة عبر الواجهة والخدمة وSQL، مع المصادر المتعارضة وإعادة التحميل والانقطاع والهاتف. يسجل سجل التنفيذ نتيجة المتصفح النهائية بعد تشغيله مع بقية المراحل. جميع عمليات الإرسال في الاختبارات إلى fixture محلي معلوم؛ لا تُرسل رسائل أو نماذج فعلية إلى مواقع عامة.
