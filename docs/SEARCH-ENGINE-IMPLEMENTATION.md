# محرك البحث — التنفيذ والتحقق المحلي

**تحديث لاحق في 8 نوفمبر:** راجع [استكمال البحث ومراجعة الصلة](SEARCH-COMPLETION-2026-11-08.md) للبوابة المشتركة للمزودين الخمسة وCAS التحديث والتنظيف الدوري والعبارات المقتبسة وترتيب الغرض الأكاديمي وسياسة v4 وأدلة جولات التطوير المتكررة. تبقى الأرقام والحدود أدناه سجلًا للجولة السابقة حيث تختلف عن التحديث.

الحالة في 8 نوفمبر 2026: نُفذ بحث حتمي بمصادر عامة متخصصة، وتخزين SQL بنطاق المالك، وفهرس محلي لروابط يضيفها المالك صراحةً. هذا التقرير يحدّث عبارة «لم يبدأ التنفيذ» في [الخطة السابقة](SEARCH-ENGINE-PLAN.md)، ولا يعلن اكتمال الخطة أو جاهزية إنتاجية.

## المصادر المنفذة

| المصدر | العقد المستخدم | حدود التغطية |
|---|---|---|
| Wikipedia بالعربية أو الإنجليزية | [MediaWiki Action API: Search](https://www.mediawiki.org/wiki/API:Search)؛ `action=query&list=search` | صفحات موسوعية؛ اللغة تُختار بقاعدة وجود الحروف العربية |
| Stack Exchange | [search/advanced](https://api.stackexchange.com/docs/advanced-search) على Stack Overflow | أسئلة برمجية؛ يُستدعى عند تصنيف الطلب تقنيًا |
| Crossref | [REST API](https://github.com/CrossRef/rest-api-doc)، مسار `/works` | بيانات وصفية للأبحاث، وليست قراءة النص الكامل أو تحكيم جودة البحث |
| Hacker News | [واجهة Algolia الموثقة](https://hn.algolia.com/api)، مسار `/api/v1/search` | قصص وروابط تقنية؛ ليست مصدرًا عامًا لكل موضوع |
| arXiv | [واجهة Atom الموثقة](https://info.arxiv.org/help/api/user-manual.html)، مسار `/api/query` | عنوان وملخص ورابط أعمال علمية؛ لا يثبت وجود تحكيم علمي أو صحة النتائج |

هذه المصادر لا تكوّن فهرسًا عامًا للويب، ولا تثبت أسعارًا أو طقسًا أو مواعيد حالية. لا يدخل نموذج لغوي في الاستعلام والترتيب. أصناف Bing RSS وDuckDuckGo القديمة ما زالت موجودة للتوافق، لكنها ليست ضمن المزود الافتراضي الجديد. مزودو البحث العام بالمفاتيح لم تُدمج في هذه الشريحة.

## السلوك والضوابط

- `search/engine.ts` يطبق مهلة 12 ثانية لكل مزود، واستدعاء واحد جارٍ لكل مزود في **نسخة المحرك نفسها**، وفاصلًا محليًا بين الاستدعاءات وقاطع دائرة بعد الإخفاقات. يبقى المزود مشغولًا حتى ينتهي طلبه الأصلي إذا تجاهل إشارة الإلغاء، حتى بعد عودة المهلة للمستدعي. الإلغاء لا يُحفظ كنتيجة ناجحة. لا يوجد إعادة تلقائية للطلب الفاشل.
- `providers.ts` و`extra-providers.ts` يقرآن العقود الخمسة، وينقّيان النص المعروض، ويحترمان `Retry-After` بالثواني أو التاريخ. يمنع تكرار استعلام Stack Exchange خلال دقيقة ويحترم `backoff`؛ نفاد الحصة يوقف هذا المحول محليًا 24 ساعة كحد محافظ. هذه الضوابط داخل العملية باستثناء بوابة arXiv المشتركة الموضحة أدناه. [سياسة Stack Exchange](https://api.stackexchange.com/docs/throttle) و[حدود Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/).
- arXiv لا يدخل محرك البحث دون `SearchProviderAdmission` مشترك. التطبيق والعامل يمرران مخزن SQL نفسه: صف عالمي لكل مزود ورمز ملكية، ووقت قاعدة البيانات، وطلب واحد فقط، ثم انتظار ثلاث ثوانٍ على الأقل من اكتمال النقل، أو `Retry-After` الأطول. إلغاء المستدعي أو انتهاء مهلته لا يحرر الرمز قبل انتهاء Promise النقل الفعلي؛ تحرير الرمز مقيد بالمطابقة. يتوافق هذا التصميم مع [شرط arXiv للاتصال الواحد والفاصل الزمني](https://info.arxiv.org/help/api/tou.html). اختُبر التنافس بنسختين من المخزن والمحرك وساعتي مضيف مختلفتين على PGlite، ولم يُجر اختبار متعدد الخوادم على PostgreSQL الإنتاجي.
- مسار التطبيق المشترك يستخدم `SqlSearchStore` وجدول `search_cache`: حد 200 استعلام لكل مالك، ومفتاح مبصوم يشمل المالك والاستعلام والحد والسياسة والمزودين، دون حفظ نص الاستعلام. TTL مقداره 15 ثانية للطلب المتغير زمنيًا، ودقيقة للعام، ودقيقتان للتقني/الأكاديمي، وعشر ثوانٍ للنتيجة الخالية، وسقف دفاعي خمس دقائق. يظل `fetchedAt` الأصلي محفوظًا عند الاسترجاع. لا نتيجة منتهية ولا إعادة تحقق خلفية في هذه الشريحة؛ يُعاد الجلب بطلب بحث جديد. `Map` يبقى بديلًا محدودًا للمحرك المنفرد دون مخزن SQL؛ عند غياب هوية المالك لا يُخزّن البحث.
- حذف مصدر أو تحديث الفهرس أو مسح التخزين يغير رقم نسخة المالك ويبطل ذاكرته المخزنة. لا يستطيع بحث بدأ قبل الحذف إعادة إدخال نتيجته القديمة لاحقًا. يرفض البحث العام استعلامًا يحمل نمط اعتماد معروفًا قبل الاتصال، وينقّي مقتطفات المزودين قبل تخزينها. هذه قواعد حجب محددة، وليست كاشفًا شاملًا لكل سر محتمل.
- `ranking.ts` يطبّع العربية والإنجليزية، ويحترم `site:` لنطاق صحيح، ويحذف معاملات التتبع المعروفة فقط. يجمع الروابط المتكررة بـRRF ويرتب بـBM25 على العنوان والمقتطف والمضيف، مع حد ثلاثة نتائج لكل مضيف. يختار الوصف الأكثر صلة عند تكرار الرابط. النتيجة موسومة `lexical`؛ درجتها ليست إثباتًا لصحة المحتوى أو مقياسًا لدقة شاملة.
- الاستعلام بلا موضوع بعد حذف الكلمات العامة، أو ذو قيد `site:` غير صالح، يُرفض بدل توسيع البحث بصمت. دعم العبارات المقتبسة والمرادفات والاستعلامات المركبة المحدد في الخطة لم يكتمل.
- جلب الأدلة يمر بـ`SafeNetwork` الذي يتحقق من العناوين وDNS والتحويلات وحدود الحجم. `RobotsPolicy` يفحص سياسة المصدر والتحويلات، ويستخدم قواعد المجموعات والأولوية وUTF-8 والرموز الخاصة. يدعم نهايات الأسطر CR/LF والقواعد الفارغة. فشل الجلب أو تجاوز حجم/تعقيد التحليل يمنع قراءة المصدر. ليس `robots.txt` تفويضًا أمنيًا. [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html).
- هوية قارئ المصادر قابلة للضبط في `NetworkPolicy.userAgent` وتضم افتراضيًا رابط مشروع محسن. يشترط Wikimedia تعريفًا ذا وسيلة اتصال، ويوصي بإرسال الطلبات على التوالي؛ يلزم إبقاء الهوية دقيقة ومحدثة. [آداب MediaWiki](https://www.mediawiki.org/wiki/API:Etiquette).

## دليل التحقق وحدوده

حفظ [الفحص العام](../artifacts/search-live-check.json) بتاريخ `2026-11-08T18:21:40Z` نتائج ناجحة لثلاثة طلبات: `Node.js API`، و«استكشاف الفضاء»، و`machine learning research paper`. يثبت ذلك اتصالًا فعليًا ونتائج قابلة للتحليل في تلك الجولة، قبل إصلاحات المراجعة اللاحقة. لا يثبت جودة كل النتائج أو تغطية الويب أو استمرارية الخدمة.

فحص [المصدرين الإضافيين](../artifacts/search-extra-provider-live.json) نفذ ثلاثة طلبات عامة فقط دون إعادة: واحدًا لـHacker News واثنين لـarXiv؛ جميعها HTTP 200 وثلاث نتائج قابلة للتحليل لكل طلب. فاصل بداية طلبي arXiv كان 3.472 ثانية. هذا الفحص سبق إضافة بوابة SQL، ولا يثبت التنافس متعدد العمليات أو جودة بحث عامة؛ لا يتضمن فهرسة موقع خارجي.

بعد إضافة SQL والفهرس والمصدرين وبوابة arXiv ومراجعات الاعتمادات والإلغاء نجحت **81 حالة في ثمانية ملفات** دون تجاوز؛ التقرير [search-completion-tests.json](../artifacts/search-completion-tests.json)، بالأمر:

```powershell
npx vitest run packages/browser/src/search tests/search-relevance.test.ts tests/search-index-api.test.ts
```

تغطي الإضافات عدم تداخل طلب مزود بطيء حتى بعد إلغاء المستدعي، وعزل مالكي SQL واسترجاعه من نسخة جديدة، وانتهاء الصلاحية، ومنع إعادة إدخال نتيجة سبقت الحذف، وإزالة التكرار وتغيير المفردات، واسترجاع نص متأخر، وبصمة مقتطف محلي عند تكراره في مزود حي. تغطي أيضًا منع الطلب غير المصرح وقراءة robots لكل وجهة تحويل ورفض الوجهة الخاصة وHTML noindex والأسرار المعروفة وPDF. رحلة API تستخدم خادم HTTP محليًا وPGlite مؤقتة، ولا تفهرس موقعًا خارجيًا حقيقيًا. نجح TypeScript في جولة المراجعة أيضًا.

المراجعة المستقلة كشفت حيلتي ترميز للاعتمادات وأصلحتهما الاختبارات: تُفحص العناوين والنصوص بعد فك HTML entities والتطبيع، وتُفك مقاطع percent الصحيحة للاستعلام حتى بوجود `%` حرفية في موضع آخر، قبل الاتصال بأي مزود. لا يقبل قارئ Atom DTD أو entities خارجية أو تعليمات معالجة XML، ويحد الحجم والعمق وعدد العقد. اختبار فصل العميل يثبت إلغاء طلب المصدر وإغلاق اتصاله دون حفظ مستند.

## الفهرس المحلي الاختياري SE6

`LocalPublicIndex` يقرأ **رابطًا عامًا واحدًا** من طلب المالك المصادق عليه؛ لا ملفات خاصة، ولا cookies أو credentials، ولا زحف للروابط، ولا كتابة للنموذج، ولا حفظ تلقائي لنتائج البحث. `SafeNetwork` وrobots يفحصان كل وجهة قبل طلب المحتوى؛ تُحجب HTML meta noindex و`X-Robots-Tag: noindex/none` والمصادر غير النصية والردود غير HTTP 200 وأنماط الأسرار المعروفة. رفض رأس noindex محافظ ويشمل القيود المسماة لوكيل آخر. الحد 256000 بايت للرد، و60000 حرف للنص المستخرج، و4000 مفردة مميزة، و100 مستند لكل مالك. لا تُحفظ نسخة مبتورة إذا تجاوز النص الحد.

يحفظ `search_index_documents` الرابط وبصمته وبصمة المصدر الكامل وبصمة النص المستخرج والعنوان ووقت الجلب والانتهاء؛ ويحفظ `search_index_terms` المفردات وتكرارها للترتيب اللفظي. إعادة جلب الرابط نفسه تحدّث الأوقات والبصمات، وتعيد كتابة المفردات إذا تغير المحتوى فقط. المحتوى المطابق لرابط آخر يعود كنسخة مكررة دون تجديد وقت الرابط الأصلي. يفصل المالك كل استعلام وتعديل وحذف. TTL يختاره المالك بين ساعة وسبعة أيام؛ النسخة المنتهية لا تظهر في النتائج، ويُحذف سجلها ومفرداتها عند عملية الفهرس التالية لذلك المالك. تنظيف المنتهيات **كسول** وليس مهمة دورية عالمية؛ قد تبقى البايتات في SQL إلى ذلك الوقت أو الحذف الصريح.

كل نتيجة محلية تحمل `coverage: local_only` و`freshness: indexed_snapshot` و`fetchedAt` و`expiresAt` والبصمتين و`trust: untrusted`. مقتطف البحث المرسل للمحادثة يصرح بتاريخ النسخة حتى عند اختصار حقول النتيجة. هذا تاريخ جلب النسخة، لا تاريخ تحديث الموقع. عند تطابق رابط محلي مع نتيجة مزود يُحفظ المقتطف المحلي مع بصمته بدل نسبة نص آخر إليها. لا تُرقّي الفهرسة النص إلى حقيقة متحققة أو تعليمات للوكيل.

فشل إعادة الجلب العابر يبقي النسخة القديمة بوقتها وانتهائها الأصليين دون تجديد. إذا أثبت طلب الإضافة الصريح منع robots أو noindex، تُسحب نسخ الرابط المطلوب والوجهة النهائية المعنية من فهرس هذا المالك وتُبطل ذاكرته المخزنة. لا يمس السحب مالكًا آخر أو روابط أخرى، ولا يستطيع طلب رفض قديم حذف إضافة أحدث اكتملت أثناء جلبه.

واجهات المالك: `GET/POST /api/search/index`، و`DELETE /api/search/index/:id`، و`GET /api/search/index/query?question=...` للبحث المحلي فقط، و`DELETE /api/search/cache`. إدخال POST هو `{url, ttlHours?}` فقط؛ لا يقبل هوية مالك أو نصًا أو أداة أو طلب زحف من المستدعي. طلب الفهرسة محدود بثلاثين ثانية وتلغيه بداية إغلاق الخادم.

## تعافي بوابة arXiv وحدود الإكمال

لا توجد مهلة تُجيز الاستيلاء تلقائيًا على رمز طلب arXiv؛ العملية المتوقفة قد تترك نقلًا غير محسوم. إذا تعطلت العملية وهي تحمل الرمز يبقى arXiv محجوبًا، وتبقى المصادر الأخرى متاحة. لا يوفر API أو واجهة المالك زرًا لتجاوز القفل. لاستعادة الخدمة يجب على مسؤول التشغيل أولًا إيقاف جميع عمليات API والعامل المتصلة بالقاعدة على جميع المضيفين، وإثبات توقف الاتصالات القديمة، ثم تحرير **الرمز المحدد نفسه** يدويًا مع فرض فاصل ثلاث ثوانٍ. عند تعذر الإثبات يبقى القفل قائمًا. نموذج صيانة، لا يُنفذ تلقائيًا:

```sql
UPDATE search_provider_admission
SET active_token = NULL, acquired_at = NULL,
    next_allowed_at = clock_timestamp() + interval '3 seconds'
WHERE provider = 'arXiv' AND active_token = :'verified_stopped_token';
```

يبقى من الخطة: إعادة التحقق الخلفية المعلنة للنتائج القديمة، تعميم ضبط المعدلات المشترك على بقية المزودين، مزود بحث عام إضافي، قياس صلة مستقل بمجموعة الاستعلامات المخططة، وإثبات الرحلة كاملة في بيئة النشر. البحث عن حقيقة متغيرة ما زال يحتاج فتح المصدر المناسب وقراءة دليله الحالي. اختبارات SQL الحالية على PGlite؛ لا ادعاء إثبات تشغيل PostgreSQL متعدد الخوادم.
