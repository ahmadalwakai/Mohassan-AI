# مواصفات تجربة المستخدم — Mohassan AI v4.0

التاريخ: 2026-11-04. هذا الملف يحدد السلوك المرئي ومعايير القبول، ويكمل `ARCHITECTURE.md`. ذكر مسار أو تدفق مخطط لا يعني أنه منفذ.

## 1. ما هو منفذ حاليًا

- مسار الويب المرئي الوحيد هو `/`؛ إعداد المالك والدخول واللوحة تظهر داخل الصفحة نفسها.
- التنقل الحالي يبدل عروض `overview` و`tasks` و`coding` و`studio` و`browser` و`memory` و`windows` و`capabilities` و`integrations` و`roadmap`؛ ليست هذه مسارات مستقلة منفذة.
- توجد إدارة جلسة، إعداد مالك محلي برمز، إنشاء مهمة تشخيص أو `plan.draft` أو `coding.change` عندما يعلنها سجل القدرات نشطة، وتفاصيل وأحداث وموافقة وإلغاء وعرض نتائج typed.
- مستويات المهمة الحالية: `assisted` ينتظر موافقة، و`scoped` يشغل المهمة المحددة في حدود سياستها؛ التخطيط يجيز طلب Groq فقط، والبرمجة تحتاج موافقة صريحة أيضًا بسبب الكتابة والتشغيل. `shadow` يحفظ اقتراحًا دون تشغيل أداة أو إرسال طلب نموذج.
- `system.diagnostic` فحص محلي، و`plan.draft` إعداد خطة عبر Groq عند تهيئته، و`coding.change` تعديل محدود داخل نسخة عمل معزولة عند توفر العزل. أدوات الخطة لا تشغل تلقائيًا؛ مهمة البرمجة اختيار منفصل بمشروع ونطاق وموافقة.
- اختيار التخطيط يعرض عنوانًا وهدفًا حرًا ومقاييس نجاح اختيارية، مع إفصاح عن إرسال الوصف إلى Groq في الوضعين المصرح بهما. الافتراضي الأول يظل التشخيص.
- نتيجة التخطيط تعرض الهدف ومعايير النجاح والأدلة المتوقعة والتبعيات والمجموعات والصلاحيات والقدرات غير المتاحة والأسئلة والقيود والافتراضات وعدم اليقين ومصدر النموذج وعدد التوكنات. «اكتمل إعداد الخطة» لا يعني تنفيذ الهدف.
- عرض الاتصالات يفرق بين Groq غير المهيأ والمهيأ والمتصل بعد تحقق مؤرخ والخطأ؛ زر «اختبار اتصال Groq» يوضح أنه يرسل طلبًا صغيرًا صريحًا ولا يرسل أهداف المستخدم المحفوظة. لا حقول مفاتيح في الويب.
- عرض «مشاريع البرمجة» ينشئ مشروع تجربة من الخادم أو يسجل مستودع Git محليًا بمسار يكتبه المالك ونطاق ملفات نسبي. تعرض حالة العزل الفعلية، وتغيب قدرة التشغيل عن خيارات المهمة إن لم يتوفر العزل.
- نتيجة البرمجة تعرض الإصدار الأساسي والفرع ونقطة الاستعادة وفرق الكود وبصمات الملفات واختبارات قبل/بعد وسجلاتها وحالة المراجعة المستقلة وبقاء المستودع الأصلي دون دمج. فشل الاختبار أو المراجعة ظاهر ولا يوصف بأنه تغيير جاهز.
- الملف الحالي يدعم مشروع Node صغيرًا بلا اعتماديات خارجية، ضمن 40 ملفًا متتبعًا في Git و128,000 بايت من المحتوى إجمالًا، وحتى خمسة ملفات تنفيذ مسموحة للتعديل. ليس محررًا عامًا لكل المشاريع أو أوامر البناء.
- المزوّد المحلي الفعلي على Windows هو AppContainer مع قيود نظام التشغيل وحجب الشبكة؛ AppContainer ليس جهازًا افتراضيًا ولا microVM. تعرض النتيجة اسم مزوّدها ودليل تحقق العزل بدل استنتاجه من نجاح الاختبار.
- لوحة الويب تحدث البيانات بطلبات مصادقة دورية؛ شريحة Studio ثابتة لـHTML/CSS منفذة، بينما WebSocket والاستوديو العام والمتصفح وAds وتطبيقات الأجهزة ليست منفذة.
- واجهات `/api/*` عقود خدمة فعلية وليست صفحات تنقل. يوضح هذا الملف أي تغيير لاحق إلى مسارات مستقلة.

## 3. قواعد موحدة لكل تجربة

- العربية وRTL افتراضيان؛ الشيفرة والمعرفات التقنية LTR. الأوقات تعرض محليًا مع تاريخ ملاحظة الدليل، ولا تخفي قِدم البيانات.
- الإجراء يذكر المورد والأثر والنطاق والمدة؛ حساسية القدرة تحكم الموافقة مهما كان مستوى الاستقلالية المختار.
- الحالات الأساسية: **تحميل** له وصف؛ **فارغ** له خطوة بداية؛ **خطأ** له سبب آمن؛ **غير متصل** له وقت آخر تحديث؛ **تعافٍ** يعيد القراءة أولًا؛ **رفض صلاحية** يشرح النطاق المطلوب دون كشف مورد غير مملوك.
- لا إرسال تلقائي لموافقة أو تعديل معلق عند عودة الشبكة. إعادة طلب غير محسوم تحافظ على مفتاحه؛ لا تنشئ عملية ثانية بصمت.
- الحوارات تدير التركيز وEscape والعودة إلى العنصر السابق؛ الأزرار والحقول مسماة، وحالات التنفيذ لا تعتمد على اللون وحده، وتراعى تفضيلات تقليل الحركة.
- تعرض الواجهة ملخصًا مفهومًا وأدلة اختيارية؛ لا مفاتيح أو رموز أو مسارات خارج نطاق المشروع المصرح به في لقطة حالة أو إشعار أو خطأ. مسار المشروع الذي سجله المالك يظهر له في عرضه المصادق عليه. لا تخزين لبيانات المالك في `localStorage`.

## 5. المحادثة وتحويل الهدف — منفذ جزئيًا ومخطط لاحقًا

إعداد خطة منظمة من هدف حر متاح عبر نموذج إنشاء المهمة عند تفعيل `plan.draft`؛ المحادثة المستمرة وتحرير إصدارات الخطط وربط تنفيذ أدوات متعددة تبقى مخططة. خطوات التخطيط الحالية تعرض الصلاحيات المقترحة وavailability دون منحها. تقدير ثقة النموذج يعرض كتقدير للخطة، لا احتمال نجاح مثبت.

1. يكتب المستخدم هدفًا، ويرى الموارد المتاحة وحدود الوقت والتكلفة؛ يراجع النظام الهدف ومعايير النجاح المقترحة قبل enqueue.
2. تعرض الخطة الخطوات والاعتماديات والأدوات ونقاط الموافقة؛ تعديلات المستخدم تنتج إصدار خطة جديدًا وتبطل الموافقات المتأثرة.
3. يرتبط رد المحادثة بالمهمة ونتائجها؛ «تم» يتطلب نتيجة verifier، والمعلومات الناقصة تعرض كعدم يقين مع مصدرها.
4. تحميل: تقدم فهم/تخطيط دون ادعاء التنفيذ؛ فارغ: أمثلة لا تنفذ تلقائيًا؛ خطأ: سبب محدود وإعادة صياغة؛ offline: مسودة محلية في ذاكرة الصفحة فقط؛ تعافٍ: جلب إصدار المحادثة؛ رفض: تحديد القدرة غير المسموحة.
5. القبول: فشل النموذج لا ينشئ مهمة ناقصة؛ الأدلة ومصادرها تبقى منفصلة عن النص التفسيري؛ لا أداة ذات أثر تستدعى من الرد مباشرة.

## 6. Studio: الشريحة الثابتة الحالية والتوسع المخطط

المنفذ حاليًا عرض «الاستوديو البصري» ضمن مساحة العمل. يختار المالك جلسة محفوظة، أو ينشئ تجربة، أو يستورد مجلد HTML/CSS داخل جذور القراءة المصرح بها. يقرأ الخادم المجلد مرةً ويحفظ الأصل والنسخة الحالية في SQL، دون تشغيل أو تعديل المشروع المستورد. لا يتطلب هذا المسار Git أو Groq أو تشغيل AppContainer، لأنه لا ينفذ كود مشروع.

تعرض المعاينة أحجام سطح المكتب والهاتف، ووضع اختيار العناصر. يظهر العنصر المحدد وملفه وسطره، مع تحرير النص المباشر أو اللون أو الخلفية أو حجم الخط. العنصر ذو أبناء لا يقبل استبدال محتواه نصيًا؛ يختار المستخدم عنصرًا نصيًا أدق. تعكس المسودة التغيير في العرض، ويكتب زر الحفظ الصريح نسخة المراجعة في SQL. لا ينشئ الحفظ مهمة ذكاء أو موافقة أدوات أو worktree. يمكن عرض الأصل مع الحالي ومقارنة ملفات المصدر، والتراجع خلال آخر20 نسخة محفوظة. لا يوصف هذا بأنه اختبار تطبيق أو visual diff آلي.

تكون المعاينة `srcDoc` داخل `iframe sandbox="allow-scripts"` دون same-origin أو تنقل أو نماذج أو شبكة. يسمح CSP بجسر nonce الموثوق فقط، بينما يحجب المحرك scripts والسمات التنفيذية والموارد غير المدعومة ويحذر عند حجبها. الأصل opaque، لذلك تقبل الواجهة `event.origin='null'` حصريًا مع تطابق نافذة iframe وnonce والإصدار والعقد ومعرف العنصر المرسل. قناة `postMessage('*')` في هذه الشريحة محدودة بالتحديد والمسودة؛ لا تفوض الحفظ أو ترسل أسرارًا. لا ينطبق الاستثناء على API أو إطار آخر. يعيد الخادم اشتقاق ربط العنصر عند الحفظ.

في التحميل تظهر حالة انتظار وتتعطل الأزرار المعنية، وفشل الاستيراد أو الحفظ يعرض رسالة قابلة للفهم. عند انقطاع الخدمة تبقى آخر معاينة موسومة وتتوقف الكتابة؛ استعادة الاتصال تتطلب نسخة حديثة. تعارض revision يطلب إعادة التحميل، ولا يعيد إرسال تعديل قديم تلقائيًا. الجلسة غير المملوكة تعيد404. لا حاجة لمفتاح نموذج لإنشاء تجربة ثابتة. راجع `PHASE-5.md` للحدود الدقيقة.

### المسار الكامل المقترح — غير منفذ بعد

1. يختار المستخدم مشروعًا وبيئة، ويشاهد الفرع وإصدار المصدر وحالة sandbox؛ لا معاينة بلا بيئة معزولة جاهزة.
2. يعمل وضع التحديد داخل المعاينة، ويبرز العنصر ويرسل وصفًا بنيويًا محدودًا و`elementId` ولقطة مرتبطة بإصدار المعاينة.
3. يحول Project Intelligence الاختيار إلى ملفات ومكونات محتملة، مع مصدر الربط ودرجة اليقين؛ يعرض اسم الملف قبل أي اقتراح تعديل.
4. عند غياب source maps أو تعدد المكونات أو استخدام عنصر ديناميكي/طرف ثالث، تظهر «تعذر تحديد المصدر بدقة» مع المرشحين؛ يطلب اختيار الملف أو نطاق أوسع، ولا يزعم ربطًا مؤكدًا.
5. يصف المستخدم التعديل؛ يترجم إلى patch داخل worktree المهمة بعد التحقق من بصمة الملفات وصلاحية `code:write`.
6. ينشأ checkpoint قبل التعديل؛ يظهر ما سيتغير ثم تشغيل الفحوص الملائمة: أنواع، اختبارات متأثرين، build، ومتصفح عند الحاجة.
7. تعاد المعاينة من المصدر الجديد؛ تعرض مقارنة بصرية قبل/بعد بنفس viewport وحالة بيانات معلومة، وdiff كود ومخرجات الفحوص.
8. يراجع المستخدم النتيجة ويطلب تصحيحًا أو استعادة أو تسليمًا؛ الدمج والنشر إجراءان بصلاحيات منفصلة ولا ينتجان من مجرد قبول preview.
9. screenshot-to-code يتطلب وصف المرجع وحقوق استخدامه عند الحاجة، ويولد ملفات قابلة للتحرير عبر المحرك نفسه؛ الصورة المرجعية لا تعطي صلاحية تنفيذ.

**بروتوكول بيئة التشغيل المستقبلية:** origin منفصل لكل بيئة عن Control Plane، وiframe sandbox محدود، وCSP ومنع تمرير session cookies أو مفاتيح أو service credentials إلى preview. هذه القواعد للتشغيل العام القادم؛ استثناء الأصل opaque للشريحة الثابتة موصوف أعلاه ولا يجيز تشغيل JavaScript مشروع.

- رسالة نموذجية typed: `{version:1,type,previewSessionId,nonce,requestId,sourceRevision,payload}`؛ أنواع مسموحة مثل `ready`, `element:selected`, `highlight`, `preview:error`.
- يفحص المستقبِل `event.origin` المطابق لإعداد البيئة و`event.source` المطابق لنافذة iframe، ثم schema والحجم والجلسة وnonce وإصدار المصدر. يحدد المرسل `targetOrigin` صراحة؛ لا `*`.
- يتغير nonce عند إعادة فتح البيئة أو تحميل المعاينة. الرسائل القديمة والمكررة وorigin غير الموافق و`null` غير المصرح به ترفض وتوثق دون تنفيذ.
- رسائل التحديد بيانات غير موثوقة، ولا تقبل رسائل shell أو write أو طلبات API حرة؛ التعديل يمر من Control Plane بصلاحيات المستخدم.

| الحالة | السلوك المرئي المطلوب |
|---|---|
| نجاح/تحميل/فارغ | الاختيار يظهر مصدره وإصدار المعاينة؛ مراحل تجهيز/patch/اختبار واضحة؛ مشروع فارغ يعرض استيرادًا أو إنشاءً مصرحًا |
| خطأ | يعرض فشل build أو console منقحًا مع الملف المحتمل؛ يحتفظ بآخر preview ناجحة ويفصلها عن النسخة الفاشلة |
| غير متصل/تعافٍ | معاينة قديمة موسومة؛ التعديلات معطلة؛ بعد الاتصال تقارن revision الحالية قبل إعادة الاقتراح أو الاختبارات |
| رفض صلاحية | يسمح بالقراءة المصرح بها فقط، ويشرح غياب `code:write/run/publish` دون عرض زر تنفيذ فعال |
| القبول | اختيار→مصدر→patch→اختبارات→diff→مراجعة يعمل على مشروع اختبار؛ رسالة مزورة لا تعدل كودًا؛ mapping غير مؤكد لا يؤدي لكتابة عمياء |

## 7. البرمجة ونقاط الاستعادة والتعارض — شريحة محدودة منفذة

1. يفتح المالك «مشاريع البرمجة»، ويرى هل العزل متاح ومزوّده. إنشاء المشروع التجريبي لا يشغل كوده؛ تسجيل مشروع آخر يتطلب مسارًا صريحًا داخل جذور الخادم المسموح بها، ومستودعًا نظيفًا محفوظًا في Git ونطاقًا من ملف إلى خمسة ملفات تنفيذ.
2. النطاق الحالي مشاريع Node بلا حزم خارجية: حتى 40 ملفًا متتبعًا في Git و128,000 بايت إجمالًا. ملفات الاختبار والإعدادات المحمية ليست أهداف تعديل؛ لا إدخال shell أو تشغيل scripts من package.json أو npm install أو أمر اختبار حر من الواجهة.
3. يختار المستخدم `coding.change` ومشروعًا وهدفًا. تظهر الملفات المسموح بها وإفصاح إرسال الهدف ومحتواها للنموذج؛ الكتابة وتشغيل الاختبارات يحتاجان موافقة حتى في `scoped`. `shadow` لا يستدعي النموذج ولا يكتب ولا يختبر.
4. بعد الموافقة تنفذ المهمة على worktree وفرع مستقلين. تختبر نسخة الأساس والتعديل بملف `node-test` الثابت داخل بيئة العزل؛ لا يعد نجاح عملية على المضيف دليل عزل، ولا يسمح بالمتابعة عند عدم تحقق العزل.
5. تعرض النتيجة `baseCommit` و`branch` وcheckpoint عند إنشائه، وdiff نصيًا مع −/+ وبصمتي كل ملف، واختبارات قبل/بعد برمز خروج وtimeout ومدة ومزوّد ونوع عزل وشبكة ومخرجات اختيارية.
6. تعرض فحوص المراجعة المستقلة و`sourceUnchanged` و`worktreeRetained`. «جاهز للمراجعة» يتطلب نتيجة جاهزة وفحوصًا ناجحة ومصدرًا أصليًا ثابتًا واختبارًا ناجحًا بعزل متحقق؛ لا يعني دمجًا أو نشرًا أو تنفيذ هدف أوسع.
7. فشل الاختبار أو المراجعة يظهر بعنوان فشل واضح، مع أدلة النتيجة وحالة الاحتفاظ بنسخة العمل. لا يوجد زر دمج أو نشر أو استعادة تلقائية في الشريحة الحالية؛ checkpoint معرّف لمراجعة محفوظة وليس إقرارًا بدمجها.

**حد العزل الحالي:** AppContainer آلية عزل على Windows تشارك نواة نظام التشغيل، وتطبق صلاحيات محدودة وقيود عملية وشبكة. ليست VM، ولا تكافئ حدود عزل microVM؛ اعتماد مزوّد VM لاحقًا يحتاج تنفيذه واختباره وعرض نوعه الفعلي. نجاح اختبار Node وحده لا يثبت تحقق هذا الحد.

| الحالة | السلوك الحالي ومعيار القبول |
|---|---|
| تحميل/فارغ | إنشاء المشروع وتسجيله لهما مؤشر انتظار ومنع نقر متزامن؛ قائمة فارغة تدعو لمشروع تجربة أو تسجيل صريح؛ لا جهاز عزل أو نتيجة اختبار مصطنعة |
| خطأ | مشروع خارج الجذور أو غير نظيف أو كبير أو ذو اعتماديات/ملفات غير مسموحة يرفض قبل التشغيل؛ النتيجة الفاشلة لا تصطبغ كجاهزة للمراجعة |
| غير متصل/تعافٍ | التسجيل والإنشاء وإرسال المهمة والموافقة تتعطل عند offline؛ عند العودة تحدث قائمة المشاريع وحالة المهمة، ولا يعاد طلب تعديل غير محسوم تلقائيًا |
| رفض صلاحية/عزل | مورد غير مملوك لا يكشف؛ غياب العزل يمنع خيار التنفيذ؛ موافقة المهمة لا تجيز ملفًا آخر أو دمجًا في الأصل |
| الدقة والاستمرار | تعرض الاختبارات اسم المزوّد و`isolationVerified` وexit/timeout؛ إعادة تحميل المهمة تستعيد diff وcheckpoint والأدلة من الخادم دون إعادة التشغيل |
| القبول المثبت للتدفق | مشروع التجربة أظهر baseline exit 1 ثم تعديل الجمع واختبار exit 0 داخل AppContainer فعلي، مع checkpoint ونسخة عمل محتفظ بها وثبات الأصل وعدم الدمج؛ رد النموذج في اختبار المتصفح مضبوط للاختبار، ولا يثبت جودة تعديل كل هدف حر |

راجعت لقطات سطح المكتب والهاتف عرض المقارنة ونقطة الاستعادة وبقاء الأصل وملاءمة العرض الضيق. التدفق التالي يظل مخططًا: اختيار checkpoint واستعادته من الواجهة، ومحرر تعارض ثلاثي base/current/proposed، ودعم أطر وحزم وأوامر بناء عامة، والدمج والنشر. قبولها لاحقًا يحتاج منع طمس التعديلات المتزامنة وإثبات استعادة بصمة معلومة واختبار المستهلكين المتأثرين.

## 8. المتصفح والبحث — مخطط

- يبدأ المستخدم بجلسة وهدف ونطاق مواقع؛ تظهر هوية الجلسة ووضع القراءة وسجل إجراءات منقح، وتفصل الجلسات cookies وملفات التنزيل.
- البحث يعرض سؤالًا وخطة مصادر ومقتطفات وتاريخ وصول وروابط أصلية ونقاط اتفاق وتعارض، ويطلب أدلة إضافية عند نقص اليقين.
- تعبئة نموذج تعرض القيم والوجهة ثم موافقة `browser:submit` قبل الإرسال؛ تعليمات المواقع لا تعدل هدف المستخدم أو grants.
- تحميل: مرحلة قراءة/مقارنة مع إمكانية إلغاء؛ فارغ: لا مصادر أو نتائج مع توسيع بحث اختياري؛ خطأ: صفحة محجوبة/محتوى مفقود دون اختلاق؛ offline: نتائج سابقة موسومة؛ تعافٍ: قراءة حالة الصفحة قبل تكرار فعل؛ رفض: نطاق/SSRF/إرسال غير مصرح يوقف الخطوة.
- القبول: مصدران متعارضان يبقيان ظاهرين؛ prompt injection داخل صفحة لا يرسل بيانات؛ فقد الرد بعد submit يفتح reconciliation بدل تكرار الإرسال؛ يثبت النجاح من حالة الصفحة أو إيصال فعلي.

## 9. Google Ads: تدقيق إلى تطبيق مضبوط — مخطط

| الإجراء | ما يراه المستخدم والصلاحية المستقلة | معيار القبول |
|---|---|---|
| ربط وقراءة وتدقيق | حساب عميل/مدير محدد، عملة ومنطقة زمنية، مدى بيانات وتاريخ مزامنة؛ `ads:read` | لا أسرار OAuth مرئية؛ الحساب غير المملوك غير قابل للعرض |
| إنشاء مسودة | كلمات وإعلانات واستهداف وأسباب وتوقعات معلنة كفرضيات؛ `ads:draft` | لا تفعيل أو تغيير إنفاق عند حفظ المسودة |
| تفعيل حملة | مراجعة account/campaign وملخص الإعدادات وحدودها؛ `ads:activate` وموافقة لبصمة النسخة | تغيير المسودة بعد الموافقة يبطلها؛ لا تفعيل مكرر عند retry |
| تعديل ميزانية | قيمة قبل/بعد وعملة ومدى أثر وسقف؛ `ads:budget` وموافقة مستقلة | إذن تفعيل حملة لا يجيز زيادة ميزانية؛ سقف الإنفاق يطبق من الخادم |
| إيقاف | المورد والسبب والأثر المتوقع؛ `ads:pause` مستقل | الإيقاف لا يحذف الحملة؛ التحقق من حالتها الفعلية بعد الطلب |

- تعرض جودة التحويلات قبل التحسين: اكتمال الحجز المؤهل، dedup، تأخر الإسناد، وفترة اكتمال البيانات؛ انخفاض النقرات وحده لا يثبت تحسن CPA.
- يبدأ التحسين بـ shadow: اقتراح مقابل نتيجة لاحقة، ولا زر «تطبيق الجميع» يتجاوز موافقات activate/budget/pause أو الحساب المحدد.
- تحميل: مزامنة paginated مع watermark؛ فارغ: لا بيانات/تحويلات مع شرح الفرق بين صفر وبيانات ناقصة؛ خطأ: token/rate limit وتأخر بيانات منفصل؛ offline: آخر مدى ووقت مزامنة؛ تعافٍ: تحديث المورد والتحقق من إيصالات pending؛ رفض: scope ناقص يعطل الإجراء فقط.
- القبول: لا تحسين إنفاق تلقائي قبل اجتياز tracking gate؛ تحويل مكرر لا يحتسب حجزين؛ نتيجة apply غير محسومة لا تعاد قبل reconciliation؛ يعرض audit القرار والنسخة والموافقة والإيصال.

## 10. iPhone وWindows: الثقة والتحكم — مخطط

- SwiftUI: تبويبات مساحة العمل والمهام والبرمجة والمتصفح والإعلانات والأجهزة؛ جلسة محفوظة في Keychain، وموافقات تربط المهمة بالمورد والمدة ولا تعتمد على وجود الهاتف وحده.
- pairing: Windows يعرض challenge قصير العمر؛ iPhone داخل جلسة موثوقة يعرض اسم الجهاز وبصمة مفتاحه وصلاحيات view/control منفصلة؛ يؤكد المستخدم التطابق ثم يسجل الربط.
- remote toggle يعرض الجهاز المختار والصلاحية ووقت الانتهاء وحالة الخادم؛ لا يظهر «مفعّل» قبل إيصال grant فعلي. تعطيله يمنع أوامر جديدة ويلغي جلسات التحكم ويعرض نتيجة الإيقاف.
- رفض الثقة أو انتهاء الجلسة أو revoke يقطع stream ويمنع input؛ بقاء بعض مهام السحابة يظهر منفصلًا ولا يوحي بأن toggle أوقفها.
- APNs إشعار مقتضب مثل «مهمة تحتاج مراجعتك» ومعرف غير حساس؛ فتحه يعيد المصادقة وجلب الحالة؛ لا أزرار إشعار تطبق موافقة حساسة دون مراجعة محدثة.
- Windows service يتحقق من grant، وsession helper يعمل داخل جلسة المستخدم مع مؤشر مشاهدة/تحكم مرئي وزر «إيقاف التحكم الآن» محلي؛ local stop له أولوية ولا يحتاج اتصال السحابة.
- الشاشة تعرض حالة اتصال وزمن آخر إطار؛ UI Automation قبل vision، وفعل مهم يتبعه تحقق جديد. قفل Windows أو فقد helper يوقف الإدخال ولا يتجاوز secure desktop.

| الحالة | السلوك ومعيار القبول |
|---|---|
| نجاح/تحميل/فارغ | connecting لا يسمح بالإدخال؛ نجاح pairing يظهر الصلاحية والمدة؛ لا أجهزة يعرض بدء ربط ولا جهازًا تجريبيًا |
| خطأ | challenge منتهٍ يتطلب رمزًا جديدًا؛ فشل helper/stream له رسالة محددة وإيقاف آمن؛ لا ادعاء أن ضغط المؤشر تحقق |
| غير متصل | الهاتف يعرض snapshot موسومة ويعطل الموافقات والتبديل؛ لا input queued؛ Windows يستطيع local stop دون الشبكة |
| تعافٍ | يعاد التحقق من session/device trust/grant والحالة والشاشة؛ لا استئناف تحكم أو إرسال موافقات offline تلقائيًا |
| رفض صلاحية | view-only لا يقبل keyboard/mouse حتى من عميل معدل؛ revoke يقطع التحكم القائم ويظهر سببه المسموح |
| قبول متكامل | revoke أثناء فعل يمنع الفعل التالي؛ toggle off يوقف جلسة الجهاز المحدد وتستمر مهمة سحابية مستقلة؛ local stop يمنع الإدخال حتى لو تعذر وصول الإشعار للخادم |

## 11. بوابة قبول الواجهات المستقبلية

لا تتحول أي وحدة إلى «متاحة» قبل اجتياز happy path وحالات التحميل والفراغ والخطأ والانقطاع والتعافي والرفض من المتصفح أو الجهاز الفعلي المناسب. تُثبت آثار الأدوات بإيصالات أو نتائج مستقلة، وتختبر حدود الملكية وإلغاء الصلاحية والطلبات المتكررة. تبقى هذه التدفقات مخططة حتى توجد ملفات تنفيذ واختبارات وأدلة تشغيل تخصها.

## توسعة منفذة: React وصفحة Next البسيطة

في الاستوديو أزرار إنشاء تجربة React وصفحة Next، واختيار نوع المشروع عند الاستيراد. يبدأ العرض بعد فعل مستخدم صريح ينفذ المكوّن داخل AppContainer بلا شبكة. توضح الواجهة أن الناتج أولي، وأن الأحداث والتوجيه وخدمات Next غير مشغلة. يعرض شريط الدليل مزوّد العزل وإصدار المصدر؛ فتح الصفحة وقراءة الأصل والتراجع يستخدم الأثر المحفوظ.

اختيار عنصر يكشف ملف JSX/TSX وسطره، وتظهر الخصائص المحسوبة في المعاينة. النصوص الديناميكية والعناصر المكررة والربط غير الدقيق لا تقبل التخمين؛ التنسيق الديناميكي وقواعد!important توقف حقول التنسيق المعنية بالنسخة. يظل المستخدم قادرًا على مراجعة المصدر وتنزيله.

الحفظ يعطل الكتابة مؤقتًا ويعيد بناء العرض داخل العزل. النجاح يحدّث المصدر والمعاينة معًا؛ الخطأ يبقي آخر نسخة ناجحة ويعرض السبب مع خيار إعادة تحميلها. revision قديمة ترفض409، ولا تؤدي عودة استجابة بناء قديم إلى طمس تراجع أحدث. يدعم العرض الهاتف والمقارنة مع الأصل وسجل التراجع القائم.


## تحديث تجربة المراحل5–8

- الاستوديو: وصف تغيير أو إرفاق PNG/JPEG في المشروع المحدد؛ الرفع يحفظ صورة خاصة فقط. تفاصيل المهمة تفصح عن إرسال الملفات والصورة بعد الموافقة. النتيجة تعرض المصدر والصورتين والتغير المقاس ونقطة Git. زر التطبيق منفصل، ثم تتحدث المعاينة دون إسقاط تجربة غير محفوظة، ويتاح undo. تشغيل Next الحي يظهر غير مجهز إلى حين ربط المشغّل، ثم بناء في الخلفية وجلسة عشر دقائق وإيقاف صريح.
- المتصفح والبحث: جلسة بنطاق HTTPS ومدة، ومشاهدة وروابط ونماذج وسجل. إرسال نموذج يحتاج مراجعة وجهته وحقوله وموافقة لمرة واحدة؛ البحث يبقى محفوظًا عند مغادرة العرض ويبين المصادر والتوقيت وحدود المقارنة.
- الذاكرة والتعلّم: إضافة وبحث وتصحيح وإصدارات ومصادر وانتهاء، وإلغاء أو حذف صريح. اقتراح المهارة يحتاج اختبارًا ومقارنةً وقرار تفعيل؛ التفضيل الدائم يحتاج موافقة مستقلة.
- Windows: إنشاء رمز ثم ربط المرافق محليًا، واختيار نافذة وموافقة الجهاز، ثم إذن مؤقت من الويب للمشاهدة أو الإدخال. واجهة الهاتف تستجيب دون تفعيل جهاز تلقائيًا. زر STOP المحلي يظل سلطة الإيقاف، وتسجيل الخروج يلغي صلاحيات الجلسة ورموزها المعلقة.
- قائمة التنقل قابلة للتمرير على الشاشات القصيرة؛ تعطّل الكتابة عند انقطاع اتصال التطبيق. الحالة التشغيلية لا تستنتج نجاح عمل تجاري من مجرد إرسال نقرة أو نموذج.
