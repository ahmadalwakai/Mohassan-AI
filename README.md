# Mohassan AI

موحسن مساعد عام: تكتب طلبك في محادثة واحدة، فيبحث ويفتح المواقع وينفذ الخطوات ويتحقق من النتيجة، ثم يرد عليك. الأدوات الأخرى (المهام، البرمجة، الاستوديو، الذاكرة، Windows) متاحة من قائمة الحساب ← «الأدوات المتقدمة».

**كيف يعمل عقله:** ما يمكن تقريره من الصفحة أو الطلب يُقرر دون نموذج (فتح موقع، رفض ملفات الارتباط، تمييز صفحة الدخول أو الكود أو التحقق البشري). يُستدعى نموذج المالك المحلي عند الحاجة فقط، للتخطيط والتعافي ومراجعة الرد النهائي والخطوات التي لا يحسمها المنطق الثابت. راجع [apps/server/src/assistant/brain.ts](apps/server/src/assistant/brain.ts).

**تسجيل الدخول:** عند الوصول إلى صفحة دخول أو كود تحقق يتوقف ويطلبهما في بطاقة آمنة، ثم يكمل المهمة من حيث توقف. تذهب القيم إلى الموقع مباشرة، ولا تصل إلى النموذج أو قاعدة البيانات، وتُمسح من الذاكرة بعد الدخول، وتُستخدم للموقع الذي طُلبت له فقط. يحتفظ المتصفح بجلسة الدخول في `.data/browser-profile` للمهام القادمة.

**ما يبقى لك:** CAPTCHA وموافقات الهاتف وبيانات البطاقات تنفذها بنفسك من لوحة المتصفح بالنقر على الصورة. وقبل الدفع أو الحذف أو الإرسال أو النشر أو تغيير إنفاق الإعلانات يطلب موافقتك. تعتمد هذه الموافقة على اسم الزر وتقدير النموذج، لذلك قد تفوتها حالات نادرة.

تحديث المراحل5–8: يعمل الاستوديو محليًا مع تعديل العناصر، وطلبات تعديل بالوصف أو الصورة عبر محرك المهام وموافقاته، وصور مقارنة وفروق Git وتطبيق منفصل قابل للتراجع. أضيف المتصفح والبحث بالمصادر، والذاكرة والمهارات المقاسة، ومرافق Windows مع ربط يدوي ونطاق ومدة للمشاهدة والإدخال. تشغيل Next الكامل يتطلب جسر Vercel Sandbox مجهزًا؛ الإعداد الحالي غير مفعّل، ولا يمثل الكود أو اختبار النقل البديل إثبات تشغيل سحابي فعلي.

المراجع الحالية: [التعديل الذكي والصور](docs/PHASE-5-AI.md)، [تشغيل Next المعزول](docs/PHASE-5-LIVE.md)، [المتصفح والبحث](docs/PHASE-6.md)، [الذاكرة والتعلّم](docs/PHASE-7.md)، [مرافق Windows](docs/PHASE-8.md). سجل [حالة التنفيذ](docs/IMPLEMENTATION-STATUS.md) يميز النتائج الحالية عن التحقق التاريخي للمراحل السابقة.


تنفيذ تدريجي لخطة v4.0: مساحة عمل عربية مع مصادقة، مهام محفوظة في PostgreSQL، ونواة تخطيط تعمل بنموذج المالك المحلي عبر Ollama، ومحرك برمجة معزول مع Git Worktrees واختبارات ومراجعة تغييرات دون دمج تلقائي.

المشروع بدأ من ملف التعليمات وحده. أُعدّت [المواصفات](docs/ARCHITECTURE.md) وخضعت لـ[مراجعة مستقلة](docs/ARCHITECTURE-REVIEW.md) قبل كتابة الكود. النسخة الحالية تغطي Foundation وRuntime ونواة الذكاء والتخطيط وشريحة البرمجة المعزولة؛ بقية قدرات الخطة تظهر بحالتها الحقيقية.

وثائق المشروع: [المعمارية والمراحل](docs/ARCHITECTURE.md)، [عقود API](docs/API-SPEC.md)، [نموذج البيانات](docs/DATA-MODEL.md)، [تجارب المستخدم والأجهزة](docs/UX-SPEC.md)، [نتائج التنفيذ والتحقق](docs/IMPLEMENTATION-STATUS.md). تفصل الوثائق بوضوح بين العقود المنفذة والتصميم المقترح للمراحل التالية.

تفاصيل [المرحلة الثالثة](docs/PHASE-3.md) تشرح حدود التخطيط والتوكنات والتعافي. حفظ خطة لا يمنح إذن تنفيذ أدواتها.

تفاصيل [المرحلة الرابعة](docs/PHASE-4.md) و[حدود العزل](docs/ISOLATION.md) تشرح البرمجة والاختبارات والمراجعة. دعم الشريحة الحالي لمشاريع Node صغيرة؛ AppContainer عزل نظام Windows وليس VM.

أُضيفت شريحة تشغيلية من [المرحلة الخامسة](docs/PHASE-5.md): استوديو للصفحات الثابتة HTML/CSS، بمعاينة مباشرة واختيار عناصر وربطها بالمصدر، وتعديل النص والألوان والحجم، وحفظ نسخة مراجعة في SQL ومقارنتها بالأصل والتراجع عن آخر تعديل. توسعت هذه الشريحة بمسار التعديل الذكي والصور المذكور أعلاه؛ تشغيل Next التفاعلي يحتاج ربط المشغّل السحابي.

أُضيفت بعدها [معاينة React المعزولة](docs/PHASE-5-REACT.md): اختر «إنشاء تجربة React» أو «إنشاء صفحة Next» لتوليد الناتج الأولي الحقيقي للمكوّن داخل AppContainer. يمكن استيراد مشروع صغير يستخدم React وملفات JS/TS/JSX/TSX وCSS محلية، واختيار عنصر لتعديل ملف مكوّنه. يعاد العرض داخل العزل قبل الحفظ؛ فشله يبقي آخر مصدر ومعاينة ناجحين. فتح المعاينة أو التراجع يستخدم الأثر المحفوظ دون إعادة تشغيل المشروع. صفحات Next البسيطة تدعم layout مجاورًا، وهذا العارض الأولي لا يشغل خادم Next أو تعليمات package. المسار السحابي الاختياري يبني Next فعليًا بمكتبات موثوقة قبل إتاحة جلسة تفاعلية، ويحتاج إعدادًا مستقلًا كما يوضح PHASE-5-LIVE.

من «الاستوديو البصري» اضغط «إنشاء تجربة بصرية»، ثم اختر عنوانًا أو عنصرًا من المعاينة. تظهر التجربة مباشرة قبل «حفظ التعديل». الحفظ يحدّث النسخة الخاصة ويترك ملفات المشروع المستورد كما هي. المقارنة تعرض الأصل والنسخة المحفوظة، والتراجع يستعيد آخر إصدار. يمكن استيراد مجلد مستقل لملفات HTML/CSS داخل `CODING_ALLOWED_ROOTS`؛ حد الشريحة 40 ملفًا و128000 بايت. لا تُشغّل المعاينة JavaScript المشروع أو أوامر بناء أو تثبيت اعتماديات.

## التشغيل المحلي على Windows

تحتاج Node.js 24 وnpm. من مجلد المشروع:

```powershell
npm install
npm run dev
```

افتح http://127.0.0.1:3000. تُنشأ أسرار جلسة وخدمة محلية داخل `.data`. يستخدم التطبيق `DATABASE_URL` عند تجهيزه؛ الإعداد الحالي مربوط بـNeon فعليًا مع التحقق من TLS. عند غياب الاتصال يستخدم PGlite للتطوير في عملية واحدة فقط.

في أول تشغيل، افتح الملف `.data/setup-token` محليًا وانسخ رمزه إلى نموذج إنشاء المالك. اختر بريدك وكلمة مرور من 12 حرفًا على الأقل. لا يوجد حساب أو كلمة مرور افتراضيان. الرمز لا يُرسل في ردود HTTP، والتسجيل العام مغلق. بعد إنشاء المالك تصبح الشاشة لتسجيل الدخول.

بعد الدخول، اكتب طلبك وأرسله. يعمل المتصفح على جهازك ويظهر بجانب المحادثة أثناء العمل.

المهمة محدودة بـ 40 خطوة و15 دقيقة، ثم يسألك كيف يتابع. أرسل «تابع» لإكمال مهمة توقفت.

للفحوص التشغيلية المتقدمة، انتقل إلى «نظرة عامة» أو «المهام والتنفيذ» وأنشئ مهمة «تشخيص مساحة العمل». اختر «بموافقتك» ليتوقف التنفيذ حتى الموافقة، أو «تنفيذ ضمن النطاق» للفحص الآمن مباشرة، أو «اقتراح فقط» للحصول على خطة دون استدعاء أداة التشخيص. افتح التفاصيل لقراءة الأحداث والأدلة. التشخيص يفحص SQL وسجل القدرات ونطاق القراءة؛ لا يحقق طلب فتح موقع، ولا يقرأ ملفاتك الشخصية أو يشغل أوامر نظام.

لإعداد خطة بالذكاء، اختر «تخطيط ذكي» في «مهمة جديدة»، واكتب هدفك ومقاييس نجاحه. يرسل assisted الطلب إلى النموذج المحلي بعد الموافقة، وscoped يجيز الطلب النصي المحدود لهذه المهمة، وshadow لا يرسل أي طلب نموذج. تعرض النتيجة الهدف والمعايير والخطوات والتبعيات والأسئلة والصلاحيات المطلوبة واستهلاك التوكنات. القدرات غير المتاحة تظل محجوبة، والخطوات محفوظة بحالة planned ولا تُنفذ.

**النموذج:** موحسن لا يستخدم أي نموذج سحابي (قرار المالك في 10 نوفمبر 2026). النموذج الوحيد هو نموذج المالك على Ollama على الكمبيوتر نفسه: اضبط `LOCAL_MODEL_NAME=qwen3.5:9b-q4_K_M` و`LOCAL_MODEL_URL=http://127.0.0.1:11434` في `.env`. يُرفض أي عنوان ليس على هذا الكمبيوتر، ولا يوجد بديل سحابي. إذا لم يُضبط النموذج أو لم يعمل Ollama، تتوقف ميزات النموذج برسالة عربية واضحة، ويبقى الجزء الثابت من المساعد يعمل (التوضيح والفحوص والموافقات). ميزات النموذج للمالك فقط حاليًا؛ الأعضاء على الخادم السحابي لا يصلون إلى أي كمبيوتر، فيبقى لهم المساعد دون نموذج.

يخدم النموذج طلبًا واحدًا في كل مرة (GPU واحد)، وينتظر ثلاثة طلبات على الأكثر، ويُرفض الزائد فورًا برسالة «مشغول». حد كل طلب يبدأ عند وصوله إلى النموذج: 120 ثانية لقرار المحادثة، و300 للخطة، و180 للبرمجة وStudio، و90 لقراءة صورة. في «الاتصالات» تظهر حالة النموذج الفعلية (مثبت، محمّل، يقرأ الصور، أو غير متاح)، ويختبر الزر النموذج بطلب صغير على هذا الكمبيوتر.

الويب والخدمة يعملان محليًا على المنفذين 3000 و4000. إيقاف أمر التشغيل يوقف عملياته. بيانات الإعداد الحالي في Neon؛ نسخة PGlite السابقة في `.data/postgres` بقيت محفوظة ولم تحذف. في وضع PGlite يمنع قفل الملكية فتح المخزن من عمليتين، وتستعاد حجوزات الإعداد المحلية غير المكتملة قبل استقبال الطلبات. لا تحذف `.data` أو أسرار الجلسة إذا أردت الاحتفاظ بالإعداد والنسخ المعزولة.

## تجربة محرك البرمجة

من «مشاريع البرمجة» اضغط «إنشاء مشروع تجريبي». يُنشأ مستودع Git مستقل به خطأ جمع واختبارات محمية. ثم أنشئ مهمة واختر «محرك البرمجة المعزول» والمشروع، واطلب إصلاح الجمع. تحتاج مهمة الكتابة والتشغيل موافقة صريحة حتى مع scoped. بعد الموافقة يُنشأ Worktree مستقل ويقترح النموذج المحلي التعديل، ثم تعمل الاختبارات داخل AppContainer، وتظهر المقارنة والنتائج ونقطة المراجعة.

يمكن تسجيل مستودع محلي نظيف ذي HEAD داخل `CODING_ALLOWED_ROOTS`، مع تحديد حتى 5 ملفات تنفيذ موجودة. حدود الشريحة: 40 ملفًا نصيًا متتبعًا بإجمالي128000 بايت، وسياق نموذج صغير، واختبارات Node المدمجة. الاختبارات والإعدادات وملفات الأسرار محمية؛ لا npm scripts أو تثبيت اعتماديات أو shell. الفرع الأصلي لا يُعدل أو يُدمج، ونسخة المهمة محفوظة للمراجعة. المحاولات القديمة لا يُكتب فوقها بعد تعطل جزئي.

العزل الحالي يحتاج Windows وWindows PowerShell من `System32` وNode. يثبت الخادم حدود AppContainer قبل تفعيل القدرة؛ لا fallback لتشغيل كود المشروع على المضيف عند فشل الفحص. المصدر والاختبارات داخل النسخة للقراءة فقط، وTEMP منفصل، والشبكة ممنوعة. تفاصيل RAM/CPU والمهل وحدود القرص في وثيقة العزل. `.env` و`.data` محميان أيضًا بصلاحيات ملفات محلية خاصة في الإعداد الحالي.

## ما يعمل الآن

- مساعد عام بواجهة محادثة: بحث، وتصفح فعلي للمواقع الحديثة، وطلب الدخول والكود والمتابعة، وموافقة للأفعال الحساسة، وسجل محفوظ.
- أقسام متقدمة متجاوبة: لوحة، مهام، تفاصيل، موافقات، قدرات، اتصالات وخطة بناء.
- Better Auth: إنشاء مالك واحد محمي برمز، دخول وخروج وجلسات SQL وملفات تعريف ارتباط HttpOnly.
- عقود Zod مشتركة، التحقق من Origin، سر داخلي بين Next والخدمة، حدود الطلبات، ردود خاصة غير مخزنة.
- طابور مهام SQL: مفاتيح منع التكرار، leases وfencing، سجل أحداث ذري، إلغاء، محاولات محدودة، موافقات محددة المدخلات والمحاولة، وفاحص مستقل للتشخيص.
- مخزن تطوير دائم وموائم PostgreSQL/Neon، ونقطة تشغيل عامل مستقلة للإنتاج.
- موائم Ollama محلي فعلي بمخرجات JSON مقيدة بالمخطط، وحدود وقت وحجم وتوكنات وحجب أسرار، ونواة Goal Compiler وModel Router وStrategy Planner وUncertainty Gate وفاحص بنية وسياسة مستقل.
- حفظ خطوات الخطة وتبعياتها في SQL وسجل استخدام النموذج. لا إعادة تلقائية لطلب نموذج غير محسوم بعد الفشل أو تعطل العامل؛ يلزم تفويض جديد. التوكنات المعروفة تبقى مسجلة حتى إذا رُفضت الخطة.
- Git Worktrees وتعديل محدود واختبارات Node معزولة ومراجعة مستقلة ونقاط Git محفوظة، مع مشروع تجريبي وتسجيل مشاريع وموافقات ونتائج فشل قابلة للفحص.
- اتصال Neon فعلي وترحيل بيانات محلية متحقق منه، وفحص تزامن عاملين وfencing على اتصالين PostgreSQL مستقلين.

## الفحص

```powershell
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

اختبارات المتصفح تستخدم مخزنًا مؤقتًا ومنفذين 3100 و4100 وبيانات اختبار فقط، وتترك حساب المالك الحقيقي فارغًا. لا تنشر مخرجات trace التي تحتوي بيانات اختبار/حسابات حقيقية عند توسيع الاختبارات. نتائج التحقق وحدوده مسجلة في [حالة التنفيذ](docs/IMPLEMENTATION-STATUS.md).

الاختبارات المعتادة تستخدم مزودًا محقونًا داخل بيئة الاختبار فقط، ولا تستعمل المفتاح الحقيقي. لاختبار النموذج المحلي الحي صراحةً، أوقف نسخة التطوير أولًا لتحرير مخزن PGlite، ثم نفّذ:

```powershell
npm run ai:check -- --live --model qwen3.5:9b-q4_K_M
npm run dev
```

يختبر الأمر النموذج ثم يجري رحلة تخطيط وموافقة وحفظ في SQL مؤقت داخل الذاكرة (يرفض `DATABASE_URL`) دون إنشاء مالك أو مهمة تجريبية في بياناتك. يحفظ تقريرًا منقحًا في `artifacts/live-plan.json`. يستدعي النموذج المحلي فعليًا ولا يغادر أي طلب الكمبيوتر؛ لا يندرج ضمن `npm test` أو CI تلقائيًا.

فحوص حية إضافية صريحة، لا تندرج ضمن الاختبارات المعتادة:

```powershell
npm run db:check -- --live
npm run coding:check -- --live
npm run assistant:check -- --live
```

الأول يتحقق من PostgreSQL الحقيقي بصفوف اختبار محددة تُنظف بعد الفحص، والثاني يستخدم النموذج المحلي والعزل الفعليين ومستودعًا وSQL مؤقتين دون إنشاء حساب وهمي في بيانات المالك. تقريرا `artifacts/postgres-check.json` و`artifacts/live-coding.json` منقحان. مشروع التجربة الحية يبقى في مجلد مؤقت مذكور في التقرير للمراجعة؛ مشاريع الواجهة ونسخها تستخدم مجلد العمل الدائم.

## تهيئة بيئة الإنتاج لاحقًا

انسخ `.env.example` إلى `.env` محليًا إن احتجت إعدادات مختلفة؛ لا تضع أسرارًا في Git أو متغيرات `NEXT_PUBLIC_`. للنشر الفعلي:

1. قاعدة PostgreSQL/Neon بـTLS في `DATABASE_URL`، وأسرار مستقلة بطول 32 حرفًا على الأقل في `BETTER_AUTH_SECRET` و`INTERNAL_API_SECRET`، وأصل HTTPS في `WEB_ORIGIN`.
2. نشر Next على Vercel مع `MOHASSAN_SERVER_URL` للخدمة الدائمة و`INTERNAL_API_SECRET`. تحتاج الخدمة رابط HTTPS يمكن لـVercel الوصول إليه. القيم محمية في بيئة النشر.
3. خدمة Node دائمة للـAPI وتشغيل `npm run server` مع `RUN_WORKER=false`. شغّل `npm run worker` في خدمة عامل منفصلة ضد قاعدة البيانات نفسها. لا تشغل عاملًا مستقلًا على PGlite.
4. إنشاء المالك عبر `npm run owner:create` بعد إعداد `OWNER_NAME`, `OWNER_EMAIL`, `OWNER_PASSWORD` في بيئة العملية الخاصة. لا تمرر كلمة المرور كوسيط في سطر الأوامر. إعداد المالك عبر HTTP معطل في الإنتاج. لا تجر عمليتي إنشاء مالك بالتوازي.
5. اختبارات PostgreSQL متزامنة، اختبار استعادة، مراقبة وأسرار KMS وحدود موارد وتشغيل، ثم موافقة الإصدار الإنتاجي. لم تُنفذ هذه التهيئة السحابية بعد.

`npm start` يشغّل بناء الويب المحلي والخدمة بإعدادات الإنتاج ويتطلب القيم السابقة وبناءً ناجحًا مسبقًا. المنفذ المحلي للويب مشتق من `WEB_ORIGIN`، أو `PORT` عند تحديده. ليس بديلًا عن تكوين Vercel وخدمة العامل.

لتشغيل الخدمة الخلفية وحدها على جهاز Windows الحالي مع واجهة Vercel، استخدم `node scripts/start-server.mjs`. يقرأ المشغّل `.env` ثم إعدادات المضيف الاختيارية في `.data/production.env` مثل `WEB_ORIGIN=https://www.mohassansy.com`؛ متغيرات بيئة الخدمة الصريحة لها الأولوية. يفرض وضع الإنتاج، ويتطلب PostgreSQL وأصل HTTPS، ويستخدم الأسرار المحددة في البيئة أو الملفين الموجودين `.data/auth-secret` و`.data/server-secret` دون توليد بدائل. يستمع افتراضيًا على `127.0.0.1:4000` ويشغّل العامل المدمج ما لم يُضبط `RUN_WORKER=false`. لا يشغّل Next ولا يفعّل التحكم البعيد بـWindows تلقائيًا.

اربط عنوان HTTPS للخدمة ومفتاحها المطابق بإعدادَي Vercel `MOHASSAN_SERVER_URL` و`INTERNAL_API_SECRET` ثم أعد النشر. يشرف `scripts/start-server.ps1` على العملية ويعيد تشغيلها بعد خروجها بانتظار متدرج من 10 إلى 30 ثانية، ويمنع تشغيل مشرفين في جلسة المستخدم نفسها. يحفظ السجلات اليومية في `.data/production-YYYY-MM-DD.out.log` وملف الأخطاء المقابل.

للتشغيل المستمر على Windows، اجعل اختصارًا في مجلد Startup للمستخدم يشغّل `pwsh.exe -NoProfile -WindowStyle Hidden -File "C:\Mohassan AI\scripts\start-server.ps1"`. يبدأ عند تسجيل دخول مستخدم Windows؛ يحتاج هذا الترتيب بقاء الجهاز مشغّلًا ومتصلًا والمستخدم مسجلًا للدخول. ملفات `.data` و`.env` خاصة ومستبعدة من Git.
